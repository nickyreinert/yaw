- Optional helpers for you while coding, not extra abilities for the agent. None of them is sent to the model.
- Session hygiene (on by default): after a prompt, a hint for you when the chat has drifted: a new topic or task, a switched branch, 60 or more prompts, 3 hours or more, or transcripts averaging 100 KB or more per prompt. Benefit: each later turn re-sends the whole chat, so a fresh chat (/handoff, then /clear) costs less and keeps answers sharp. Technically: a local check on each prompt keeps a small state in ~/.yaw (no prompt text, only a numeric topic summary), shows one message to you and repeats at most every 20 prompts. `yaw hygiene off` silences it for this project.
- Status line (Claude Code only, personal: a team repository never gets one): one line under Claude's input with the active task from TASKS.md, context used, the prompt cache when Claude reports it, a "hygiene: /clear?" badge after a hint, and whether your last plain `just check` passed. Benefit: you see the task, how full the context is and the last check result without asking. Technically: Claude Code runs `yaw statusline` on each refresh and prints one line from Claude's JSON. A `just check` you run in your own terminal is not seen.
- Notifications after long runs (off unless you choose them): a message when a run that took at least 3 minutes is done, needs your input or failed. Benefit: you can leave the chat and come back when it needs you. Channels: the terminal (a notification sequence) and ntfy or Telegram, set under Global → Settings → Notifications. Technically: the Stop, Notification and failure hooks check the run's duration; the text holds only the project folder, task id, status, minutes and task title, never code, diffs, tool output or the agent's messages. ntfy and Telegram are sent by a separate background process, so the agent never waits for the network.
- Cache reminder (Claude only, off unless you choose it): Claude's prompt cache expires after 5 minutes idle, or 1 hour when Claude Code is set to that. Benefit: before a long break you can /handoff and /clear, instead of paying again for the whole chat unnoticed. Technically: no keep-alive ping is sent. For chats of about 30,000 tokens or more, you get one line when you return after expiry saying roughly what the next prompt re-caches (estimated from the transcript size). With ntfy or Telegram set, an alert arrives about one minute before expiry (five minutes for the 1-hour cache); the timer stops when your next prompt arrives.
- They run on your machine, use no model tokens, are personal (kept in ~/.yaw, not committed) and can be changed later.
