# ADR-0055: Review module: four read-only review agents with a pre-push gate in the git-hooks frame

- **Date:** 2026-10-24
- **Category:** Modules / Workflow
- **Status:** Superseded
- **Importance:** high
- **Scope:** `modules/review/**`, `modules/git-hooks/**`, `core/lib/git-init.js`, `core/cli/review.js`
- **Tags:** review, git-hooks, pre-push
- **Superseded by:** ADR-0097

## Context

Quality checks covered only technical tools (format, lint, test). The user wanted optional sub-agents for quality, business logic, UI/UX and feature fit, enforced before code leaves the local repository, similar to gated agent frameworks.

## Decision

New optional module review (Full only). Each reviewer (quality, logic, ux, feature) is off, request (just review <kind>), suggest (Stop-hook hint for claude/codex) or push (required). Required reviewers run in a pre-push lefthook job (yaw review gate) headless through the agent CLI on the commits being pushed; results are cached per commit. quality.review-gate warn lets a person confirm on /dev/tty and push anyway; block stops the push; without a terminal (an agent pushing) warn behaves like block. pre-push lives in the git-hooks frame. Without git, reviews run only on request or as a hint; setup offers git init for a fresh folder. GitHub-side checks stay plain CI, not agent based.

## Consequences

A push can take as long as the reviews; a person can still bypass with git push --no-verify. The gate depends on the installed agent CLI's non-interactive flags. Review answers live in .yaw/answers.yaml like other module answers.
