# ADR-0103: Language id javascript renamed to typescript; old answers stay readable (T-002)

- **Date:** 2026-10-30
- **Category:** Architecture / CLI
- **Status:** Superseded
- **Importance:** normal
- **Scope:** `interview/base.yaml`, `core/interview/legacy.js`, `profiles/*/profile.yaml`
- **Superseded by:** ADR-0109

## Context

The language card was labelled TypeScript while the stored id, every profile.yaml and all examples said javascript. The mismatch hid that the stack pair means TypeScript.

## Decision

- The id is typescript in interview/base.yaml, profile.yaml stack.language, examples and tests; the card label is unchanged.
- core/interview/legacy.js maps renamed answer values (arch.language javascript to typescript). It runs when answers files are parsed, when saved presets and web or API input are read, and for languages in a pasted plan reply, so older files, presets and API calls keep working.
- Files written by the kit are not rewritten: a project's .yaw/answers.yaml keeps javascript until it is next saved.
- Session analytics and the dashboard language detection keep their own javascript label; it names a detected file type, not a stack choice.

## Consequences

A project made with this kit and checked by an older installed kit fails its sync check with an invalid-answer error until the kit is updated (yaw self-update). Future renames can add one line to the table in legacy.js.
