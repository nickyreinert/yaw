# ADR-0063: NAS remote-control concept: authoritative data hub and capability-based agent supervision

- **Date:** 2026-10-26
- **Category:** Architecture / CLI
- **Status:** Proposed
- **Importance:** normal
- **Scope:** `CONCEPT-REMOTE-CONTROL.md`
- **Tags:** remote-control, nas

## Context

A NAS can hold portable YAW data and run coding agents, but existing folder sync is a writable merge vault, the dashboard is loopback-only, and Telegram notifications do not provide session control.

## Decision

Concept proposal only: distinguish NAS data authority from agent execution; use paired clients and revision-based writes for a future hub, and a shared supervisor behind browser and Telegram interfaces. Start with one verified Claude integration, explicit session IDs, managed workspaces and routed approvals. Support new sessions and bounded workers through provider-specific adapters; do not assume control over arbitrary existing CLI processes. Evaluate native Claude Channels and Remote Control before building a bridge.

## Consequences

Implementation still needs decisions for remote authentication, sync migration, process isolation and content retention. Preserve existing sync and metadata-only registry constraints, keep credentials device-local, and make uncertain delivery or restart state visible instead of replaying work automatically. Native and SDK routes have different dependencies and authentication requirements.
