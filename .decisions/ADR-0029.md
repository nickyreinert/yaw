# ADR-0029: sessions module: registry in yaw.db, silent hooks, Agent-Session trailer, /handoff, find/for/resume

- **Date:** 2026-10-21
- **Category:** Memory / Sessions
- **Status:** Proposed
- **Importance:** high
- **Scope:** `modules/sessions/**`

## Context

Doc 12 §4 asks for a session registry, a commit trailer, a /handoff skill and session search; BD3 limits yaw.db to the registry tables; BUILD.md rule 5 allows no model-visible output except two SessionStart re-injections.

## Decision

- Three evaluation hooks (SessionStart, Stop, SessionEnd) write sessions and session_links in ~/.yaw/yaw.db and print nothing. Stop also stamps ended and links the commits that carry the trailer, and their files.
- The title comes from the active task (T-012 Title), is set once and never overwritten; registry only, no sessionTitle is returned to the agent.
- yaw gh commit appends Agent-Session: <agent>:<id> as its own paragraph; the id is the project's latest session active within 4 h, or YAW_SESSION.
- find uses the shared embedding over title, branch and links; for takes a task, ADR, commit or file; resume prints the command and never runs it.
- Every path is checked before I/O, symlinks are refused, registry text is cleaned before it reaches a terminal.

## Consequences

Concurrent sessions in one project can get each other's trailer (YAW_SESSION fixes it); decisions cited in a session, PR back-links, yaw session rename and the native sessionTitle are left for later issues.
