# ADR-0058: Cache-warmth reminder: token-free, Claude only, remote timer plus a line on return

- **Date:** 2026-10-25
- **Category:** Modules / Comfort
- **Status:** Accepted
- **Importance:** normal
- **Scope:** `modules/comfort/**`

## Context

Claude's prompt cache goes cold after 5 minutes (1 hour on a subscription); a cold cache re-bills the whole context. kickoff/11 section 3 designed a reminder but the choice stayed greyed out as phase 2.

## Decision

- Feature cache-reminder in the comfort module (user.comfort, personal features), off by default, Claude only.
- Stop records the turn end; with ntfy or Telegram configured a detached timer (cache-timer.js) sends 'prompt cache cools soon' 60 s before a 5 minute cache expires (5 minutes before a 1 hour cache) unless the next prompt or turn arrives first.
- Without a remote channel the next UserPromptSubmit says once, to the user only, that the cache went cold and about how many tokens were re-cached.
- Lifetime: CLAUDE_CODE_PROMPT_CACHE_TTL, then cache.ttl in comfort.yaml, then 5m; context size is estimated from the transcript file size (never its content); below cache.minTokens (30000) nothing is sent.
- No keep-alive ping. Output follows ADR-0007: comfort kind, systemMessage only.

## Consequences

No model tokens. The timer lives at most the cache lifetime and ends within seconds when the session moves on. The token figure is an estimate, shown with a tilde.
