# ADR-0080: Keep Quick and Basic lean and collect detailed planning constraints in Pro

- **Date:** 2026-10-28
- **Category:** Architecture / CLI
- **Status:** Accepted
- **Importance:** normal
- **Supersedes:** ADR-0076, ADR-0077
- **Scope:** `core/interview/**`, `core/web/**`, `interview/base.yaml`, `core/lib/foundations.js`, `core/lib/kickoff.js`

## Context

Live interview testing showed that framework, infrastructure, dependency and cost questions overwhelm Quick and Basic and duplicate the apparent runtime choice.

## Decision

Supersede the collection policy in ADR-0076 and ADR-0077. Quick asks purpose, language and runtime. Basic adds personal preferences per ADR-0079, repository agents, collaboration, GitHub and review gates. Pro asks every applicable question and exposes all optional tools without enabling them by default. An existing framework is an optional short constraint, separate from kit profile selection. Collect hosting control, library policy, external services and costs as short icon cards in Pro, with an optional short budget input for capped costs. Decide later remains undecided and needs discussion; no-preference invites a reasoned recommendation and grants no purchasing or provisioning authority. Preserve explicit project answers when changing depth; never reuse project constraints as personal defaults. Exact constraints still reach the shared planning prompt and structured agent context. Retain reviewed project foundations, layout and colour mockups before substantial UI implementation, separate kit practices, the shared init/Settings wizard, saved tool defaults and legacy depth compatibility.

## Consequences

The default path is shorter; detailed constraints remain reviewable and useful during planning. Unasked constraints remain undecided unless explicitly supplied. No preference does not remove data, budget or approval constraints.
