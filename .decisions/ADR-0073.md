# ADR-0073: Guided kickoff establishes three proportionate maintained project foundations

- **Date:** 2026-10-28
- **Category:** Architecture / CLI
- **Status:** Superseded
- **Importance:** normal
- **Scope:** `kickoff/**`, `core/lib/kickoff.js`, `core/cli/kickoff.js`
- **Tags:** kickoff, foundations, design
- **Superseded by:** ADR-0075

## Context

KICK-OFF.md open item 2 explores architecture/domain, data and UI/UX as connected project ground truth. Current kickoff guidance mainly produces a temporary phase/task plan.

## Decision

When guided kickoff is chosen, draft and review architecture/domain, data-model and UI/UX foundations before deriving tasks. Reuse equivalent existing documents; keep tiny projects brief and mark inapplicable persistence or human interfaces with a reason. Offer a versioned optional UI/UX guidance prompt for a configured local model or deliberate external use. Maintain one authoritative home per rule, update affected foundations with implementation and link lasting rationale to ADRs when enabled. No baseline footprint increase or new hook output is proposed.

## Consequences

The three foundations organize project intent but do not replace requirements, testing, operations, security or user validation. Needs separate prompt/import design that preserves existing task plans and user-edited documents. Main risks are duplicated truth, stale documents, excessive ceremony and treating model design suggestions as user evidence; review connected changes and validate on small and existing projects.
