# ADR-0050: Local workspace dashboard (yaw web) and next steps after init

- **Date:** 2026-10-23
- **Category:** Architecture / CLI
- **Status:** Accepted
- **Importance:** normal

## Context

Issues #167 and #172: after `yaw init` users did not know how to start, where YAW keeps sessions, tasks and decisions, or how to open the web interface; `yaw init --web` was the only browser entry.

## Decision

`yaw web` opens the local dashboard whether or not the folder has a YAW manifest. Opening it never starts setup or writes project files; configure an uninitialized folder through Workspace → Settings → Interview, where preview, apply and the folder confirmation guard remain in effect. `yaw init --web` remains the dedicated setup-form entry point. The dashboard reuses the ADR-0044 form server with the same token, cookie, Host/Origin and CSP rules. The data covers the project manifest and answers, TASKS.md, the decision index and session statistics from ~/.yaw/yaw.db for this project and all projects. Each section fails or reports "not available" independently; a missing registry is reported and never created. The client renders with textContent only. Both the terminal and the web init flow end with a "Next steps" block: start the selected agent, trust Codex hooks with /hooks when .codex/hooks.json is written, where tasks, sessions and decisions live, `yaw web`, `just --list`, `yaw doctor` and the tools the setup needs. Codex hook entries carry a statusMessage "YAW <module>: <hook names>" so the trust list is readable.

## Consequences

Amended: `yaw web --background` keeps one managed server per canonical folder running without an idle timeout. Subsequent `yaw web` calls reopen it with a fresh one-time link rather than starting competing servers. `yaw web --stop` stops it through authenticated local control (ADR-0044 amendment). After setup Apply, the background process starts the dashboard on the same port; reopen through `yaw web` to obtain its new session. Foreground behavior is unchanged.

Amendment: authenticated, CSRF-protected POST actions now support explicit saved session collection, manual local Laya classification, refresh preferences and personal notification settings/tests. Ordinary dashboard GETs never scan native history. Refresh-on-load is opt-in, unchecked by default and never classifies. Collection and classification persist aggregates, not message text, with explicit coverage limits. Historical sessions can appear after an import (#174) or explicit scan. No packages, model weights or services are provisioned automatically.

Overview is current-workspace-only. Global Projects/Sessions/Tasks are separate, with project filters; other-workspace tasks are explicit-collection snapshots. Knowledge is a separate personal/current-workspace section and excludes other projects' knowledge. Notification preferences are shared personal settings, while comfort enablement and the saved code map remain workspace-specific. See `docs/workspace-dashboard.md`.

Amendment (2026-10-24): one dashboard server can serve several projects. The browser tab names a `workspace` on every GET (query) and action (body); the server resolves it against a known-project list (`~/.yaw/web-projects.json` plus projects seen in saved session scans) and accepts only canonical folders that contain a YAW manifest, otherwise 404. The sidebar switcher keeps the choice per tab; an "Add project folder" action (`project-add`) admits a new folder under the same rule. Knowledge create/edit/delete actions are described in ADR-0053.

Amendment (2026-10-24, Settings): the sidebar is Workspace (Overview, Sessions, Settings, Knowledge, Tasks, Code map when enabled) and Global (Projects, Sessions, Tasks, Knowledge = personal records). Maintenance became Settings with Interview, Files and Notifications tabs. The browser may now write `.yaw/answers.yaml` and regenerate files through the `yaw edit` engine (explicit preview, then apply, keep strategy) and `.decisions/taxonomy.json`; both actions are CSRF-protected and hash-guarded, and a category pair used by a decision cannot be removed. Files are listed from the manifest only, read-only, without secrets; per-file change states were dropped because git tracks them.

Amendment (2026-10-25, Interview navigation): Workspace Settings is the single navigation entry for interviews. The init browser opens its interview directly after the terminal handoff; Settings offers an explicit Start interview button to return to it. In an initialized project, the same button starts the saved-answer editor. Interview views have a reversible focus mode that hides the sidebar and top bar, with an exit button in the interview heading. Leaving the interview restores the workspace chrome.

Amendment (2026-10-25, Web entry point): `yaw web` opens the dashboard even in an uninitialized or non-empty folder, without a terminal setup prompt or project writes. First-time setup is an explicit action from Workspace → Settings → Interview (or Configure project on the Overview), and the existing server-side folder confirmation protects writes. `yaw init --web` continues to open the dedicated setup form.

Amendment (2026-10-24, Global): Global is Overview (folder drill-down from the folder shared by the innermost projects), Sessions (Browse and Collect & classify tabs), Tasks, Knowledge and Settings. One sticky filter (folder, project, agent, model, period or date range) drives all cards, charts and tables; charts stack by agent, model, folder or project. Tables are filterable, sortable and paged, and all view state lives in the URL hash so views can be bookmarked. Workspace Sessions reuses the view locked to the project. Notification preferences moved to Global Settings, which also edits the personal-defaults profile and presets (preview, then apply, hash-guarded) and shows `~/.yaw` read-only. Session analysis reads transcripts without a size cap.

Amendment (2026-10-24, Classification): the Sessions tabs are gone; the sticky filter bar holds Refresh (collect; Global scope = all discovered workspaces, Workspace scope = the open one), Auto (a personal opt-in in `~/.yaw/web-preferences.json` that runs Refresh once per page load and never classifies; it replaces the per-workspace refresh-on-load) and Classify (confirmed, same scope). Global Settings gains a Classification tab: Laya address (loopback only), confidence threshold, largest turn bytes, `max_len` and timeout, validated server-side and shared with `yaw sessions evaluate`; Test connection sends one fixed made-up turn, never history. The tab and README document installing Laya in its own venv bound to 127.0.0.1; YAW still provisions nothing.

The cookie-port limitation of ADR-0044 applies to the dashboard too. Changing a hook label changes its hash, so Codex asks for trust again.
