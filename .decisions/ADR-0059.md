# ADR-0059: Web setup can take a plan from an AI chat: idea, stack and tasks

- **Date:** 2026-10-25
- **Category:** Modules / Catalogue
- **Status:** Accepted
- **Importance:** normal
- **Scope:** `core/web/**`, `core/lib/kickoff.js`

## Context

The kickoff prompt only existed in the terminal after yaw init. Users need the plan before choosing a stack, so the web interview offers it at step 3.

## Decision

- Step 3 offers a planning prompt built from the explicit answers so far (secret-checked), links to chat services and a box for the answer; nothing is sent by YAW.
- The answer has Idea, Stack and Phase sections; Idea fills idea.text (README), Stack prefills arch.language and arch.runs-on (values outside the interview lists are dropped with a warning), tasks go to docs/plan/kickoff.md and, with the tasks module in local or both mode, into TASKS.md through yaw task new; in GitHub mode the user runs yaw kickoff import.
- The plan text is sent with Apply only, never with previews or drafts. yaw init --sync and yaw web --sync join a sync folder or private repository first so presets exist.

## Consequences

Plans are plain Markdown files the CLI can import again. Chat output is untrusted input: it is parsed, size-limited and never executed.
