# ADR-0071: Remote Control is a machine-local opt-in feature

- **Date:** 2026-10-28
- **Category:** Architecture / CLI
- **Status:** Superseded
- **Importance:** normal
- **Supersedes:** ADR-0069, ADR-0070
- **Scope:** `core/lib/remote-settings.js`, `core/cli/main.js`, `core/cli/remote.js`, `core/remote/**`, `core/web/workspace-api.js`, `core/web/assets/global-settings-view.js`
- **Superseded by:** ADR-0094

## Context

The user wants Remote Control hidden and inactive during ordinary YAW use unless enabled in settings.

## Decision

Retain the private hub, isolated Claude/Codex adapters, shared browser/Telegram supervisor, authority migration boundary and environment-only credentials of ADR-0069, and all existing CLI behavior retained by ADR-0070. Add a machine-local enabled switch and port in remote-settings.json, off by default and excluded from portable sync. Global Settings / Features is the opt-in entry. Hide remote from ordinary CLI help while disabled and reject direct service, hub-client and Telegram startup. Lazily import the remote command and execution modules only after opt-in. Disabling stops a running service and its workers; retain metadata and pause migrated datasets without silently returning authority to folder sync. Invalid or unreadable optional settings fail closed without breaking ordinary commands.

## Consequences

Enabling never launches a service or configures credentials. Each host/client must opt in separately. Previously migrated data still needs an explicit authority migration before another transport may write it. Hook behavior and existing analytics remain unchanged.
