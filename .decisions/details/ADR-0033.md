# ADR-0033: `code-map` module (code map and freshness checks)

- Status: Proposed
- Date: 2026-10-21
- Issue: Y-5.11 (#139)
- Resolves: design of BUILD.md Step 5.11; applies ADR-0032 (setup depth), ADR-0004 (shared files, just `import`), ADR-0003 (ownership, `managed: false`), ADR-0007 (token-free hooks), ADR-0009 / ADR-0032 (80-line `AGENTS.md`), ADR-0019 (CLI surface), ADR-0026 / ADR-0031 (lefthook), ADR-0027 (CI job names), ADR-0022 (secret file patterns)
- Extends: ADR-0019 (phase-1 command list gains `yaw map`)

## Context

Step 5.11 asks for a concise, version-controlled map of the project for agents and people, a local index that stays correct as files change, read-only checks in the existing workflow, and no extra model tokens beyond a short navigation rule. The map must survive refreshes (maintained text is never overwritten), must not depend on GitHub or a watcher, and must not read secrets or leave the project through links.

## Decision

### Module and setup depth

- New module **`code-map`** (`modules/code-map/`), `depends: [core]`, `default: { quick: false, standard: true, full: true }`. No GitHub dependency.
- **Full only** (decided by the user on PR #140; ADR-0032 keeps the Quick list fixed). A Quick project gets it with `yaw add code-map`; the mode stays `quick` (ADR-0032). BUILD.md Step 5.11 still lists a Quick variant; this ADR does not edit BUILD.md, and the user fixes that wording.
- **`standard` copies the Full value** (`standard: true`), as ADR-0032 requires for later modules (decided by the user on PR #140). This changes a fresh `mode: standard` render, so the implementation PR regenerates the Y-5.10 byte-for-byte `standard` fixture.
- BUILD.md's "Quick" and "Full" variants of this step map to "without" and "with" the `git-hooks` / `ci` modules: the map, the rule and the explicit `update` / `check` / `show` always come with the module; the git-hook and CI checks appear only where those modules are installed.
- Existing Full projects do not get the module through `yaw update` (installed modules come from the manifest, ADR-0032); they run `yaw add code-map`.

### Files and ownership

| Path | Owner | Kind |
|---|---|---|
| `docs/code-map.md` | `code-map` | `managed: false` from the start (like a scaffold, ADR-0020): written once at init / add, never by `yaw update`; kept by `yaw remove` ("kept, owned by you") |
| `just/code-map.just` + `import` part in `justfile` | `code-map` | managed (ADR-0004) |
| `AGENTS.md` part (one line) | `code-map` | fragment (ADR-0004) |
| job in `lefthook.yml` | `git-hooks` frame, flag `codeMapModule` | managed; present only when both modules are installed |
| local index `~/.yaw/cache/code-map/<key>.json` | kit | cache, outside the project, never committed |

### `docs/code-map.md`

- **Front matter** (YAML subset, ADR-0001) holds the declarations, maintained by people and agents and never rewritten by the kit: `areas` (each `id`, `title`, `paths` globs, optional `entry`, `tests`, `relates` (area ids), `adrs`), optional `exclude` globs, optional `depth` (default 2). Relationships are declared here, not in the module: the module cannot know a project's subsystems.
- **Generated sections** sit between `<!-- yaw:map:begin <name> -->` and `<!-- yaw:map:end <name> -->`: one `overview` (area table: id, title, paths, entry points, tests) and one per area (directories of the area to `depth`, declared entry points, tests, relationships and ADRs, capped at 30 entries with "… N more, see `yaw map show <area>`"). They list directories and declared references, not files or counts, so adding a file to an existing directory does not make the map stale; a new directory, a removed directory or a changed declaration does.
- **Maintained text** is everything outside the markers: headings, responsibilities, cross-subsystem explanations. `yaw map update` rewrites only the bytes between markers; everything else stays byte for byte. A new declared area gets a heading, one placeholder line ("Describe this area's responsibility.") and its block, appended once. A block whose area was removed from the front matter is deleted; its maintained text stays and is reported for review. Unbalanced, duplicate or unknown markers: `update` refuses with `file:line` and writes nothing.
- **Starter** (init / add, only when the file does not exist): one area per top-level directory with indexed files plus `root` (`paths: ["*"]`, top-level files), so the first check passes; then the generated sections are filled. Descriptions are the user's / agent's work in a normal PR.

### Local index (cache)

- Location: **outside the project**, `~/.yaw/cache/code-map/<key>.json` (respects an absolute `YAW_HOME`; a relative one is refused, as in #124), key = first 16 hex of SHA-256 of the real path of `git rev-parse --show-toplevel` and the real path of `--git-dir`, so every worktree and clone has its own cache. Same pattern as the team sync cache (ADR-0031). Why not `.yaw/cache/` in the tree: `.yaw/` is committed today, an ignore entry would be the only thing protecting it from commits, agent search tools would still find it, and the map would have to exclude it; outside the tree none of that applies. Without a usable home the index is built in memory; results are the same.
- Content: header (schema version, kit version, the two real paths, `HEAD` and branch for information), then per file: path, size, mode, mtime and ctime (ns), inode, SHA-256. No file content, no line counts. Never injected into agent context; `yaw map show` prints a bounded view of it.
- The cache is an optimisation only: every command enumerates the working tree again, and a file whose stat tuple differs from the cache (or whose mtime is not older than the cache write, the "racily clean" rule) is re-hashed. Correctness never depends on the cache being present or recent.

### Freshness and enumeration

- Enumeration: `git ls-files -z --cached --others --exclude-standard` (fixed argv, no shell): tracked plus untracked non-ignored files, so uncommitted and untracked work counts. Tracked files missing on disk are deletions. A git work tree is required; outside one, `yaw map` exits 2 with a message.
- Changes against the cache: addition (new path), deletion (path gone), edit (stat changed and hash changed), rename (a deleted path's hash appears at a new path; hint only). Branch switches, rebases and worktree changes need no hook: the next command reconciles against whatever is on disk.
- Exclusions, applied to the path **before** any file is opened: git-ignored files; `.git/`, `.yaw/`, `node_modules/`, `vendor/`, `.venv/`, `venv/`, `__pycache__/`, `dist/`, `build/`, `coverage/`; the `secretFiles` patterns of `modules/security/guards.yaml` minus `secretAllow` (read from the kit even when `security` is not installed); front-matter `exclude`; submodules; symlinks. The cache is outside the tree.
- Path safety (reuse `core/render/files.js` rules): the project root is resolved with `realpath`; every path is checked component by component with `lstat` and skipped (reported as excluded, not an error) when any component is a symlink; files are opened with `O_NOFOLLOW` and hashed only when `fstat` says regular file; files over 8 MiB are not hashed (stat only, no rename hint). `docs/code-map.md` must be a regular file inside the root, or every command refuses.
- Determinism: paths sorted by code unit, LF, no timestamps, no absolute paths, no host data in `docs/code-map.md`; the same tree and front matter give the same bytes on every machine (test).
- Writes: `docs/code-map.md` and the cache are written to a temp file in the same directory and renamed. **No lock file** (no stale-lock handling): two concurrent cache writers each write a complete snapshot and the last rename wins, which is harmless because the cache is re-validated on every run; `update` re-reads `docs/code-map.md` right before the rename and aborts ("changed during update, run again") when it differs from what it read, so a concurrent edit is never lost.

### Commands

- `yaw map update`: refresh the cache, regenerate the generated sections, write `docs/code-map.md` only when bytes change; print the areas whose generated sections changed with "review their descriptions in this PR".
- `yaw map check`: **read-only** (writes neither the project nor the cache; it may read the cache for rename hints). Fails (exit 1) on: a generated section that differs from what `update` would write (stale, orphan or missing block); a broken reference (front-matter `entry` / `tests` / `paths` matching nothing, `relates` to an unknown area, an `adrs` ID without `.decisions/<ID>.md` when `.decisions/` exists, a relative Markdown link to a missing path); an uncovered file (indexed, not excluded, matched by no area; listed grouped by top-level directory, capped). It needs no file content except `docs/code-map.md`. Every failure ends with the repair command (`just map update`, or "declare the area / fix the reference in docs/code-map.md"). Placeholder descriptions are a warning, not a failure. Exit 2 for usage or environment errors.
- `yaw map show [area|path-prefix]`: refresh the cache (the only write), then print at most 40 lines: without an argument one line per area (id, title, file count, first sentence of its description); with an area or path prefix its description (first paragraph), entry points, tests, relationships, ADRs and files grouped by directory, capped with "… N more". A stale map is noted, exit 0.
- `just map <verb> …` runs `yaw map <verb> …` (same kit fallback as `just decisions`); the gate recipe `map-check` is in `outputs.gates`, so `just check` runs it through `sync-check` (ADR-0028); without the kit it prints a note and passes, like `decisions-check`.
- Phase 1 indexes paths and declared relationships only. Language-aware symbol or dependency extraction and a foreground `yaw map watch` (debounced, cache only) are later scope (`later`); there is no daemon.

### Agent hooks and model-visible text

- The module registers **no agent hook** in phase 1 (`tokenCost: low` for the rule only). Freshness comes from the commands, not from hooks, so nothing can print, block or call an LLM. A later hook must be `evaluation` or `comfort` and follow ADR-0007 (silent, fail-open).
- The only text the model sees is one `AGENTS.md` line (wording to be fixed in the implementation PR, ≤ 1 line): "Code map: read `docs/code-map.md` or `just map show <area>` first, then verify against the implementation, callers and tests and search wider when needed; after adding, moving or deleting directories run `just map update` and review the area descriptions." Full wording goes to `docs/spec/agent-rules.md`.
- Budget: the block costs 4 lines (rule, two markers, blank). A solo Full project renders 77 lines on `origin/main` (`d1723d9`), so it would reach 81. The implementation PR merges the two `git-hooks` rule lines into one (full text to `docs/spec/agent-rules.md`, as ADR-0032 did), giving 80; a team Full project goes from 73 to 76. The existing line-count test covers Full with `code-map`.

### Git hooks and CI

- **Git hook** (`pre-commit`, decided by the user on PR #140): when `git-hooks` is installed, its `lefthook.yml` frame gets a `pre-commit` job `code-map` (`run: just map-check`) behind the template flag `codeMapModule` (the `teamModule` precedent, ADR-0031). Not a separate `code-map` part: `lefthook.yml` composes in `lines` style, and a second `pre-commit` or `pre-push` top-level key (team already adds `pre-push`) would be invalid YAML. `pre-commit` rather than `pre-push`: the map update lands in the same commit as the structural change, and the check is cheap (no hashing). It checks the working tree like `just check`; CI checks the committed tree.
- **CI:** no new job. `quality-gate.yml` already runs `just check` on every pull-request update and push, and `just check` includes `map-check`; a separate job would need a new required-check name in the ruleset (ADR-0027).
- Checks only report. Nothing stages, commits, pushes or opens a PR; the repair is `just map update` run by a person or the agent, then a normal commit.

### Semantic review

- `yaw map check` proves mechanical freshness only: generated sections match the tree, references resolve, every file is covered. It cannot prove that maintained explanations are still true; a passing check says nothing about the architecture text.
- A structural change (a stale generated section) must come with a review of the affected areas' descriptions in the same PR; "no wording change needed" is a valid outcome. Support for that: `update` names the areas to review. The rule is guidance, not enforced. A PR-template checklist line is not part of this design: parts of shared files sort by module name, so it would land above the github template's first heading. Adding it later is a follow-up through a `githubModule` template flag.

### Removal

- `yaw remove code-map` removes `just/code-map.just`, its `justfile` import, the `AGENTS.md` fragment, the `map-check` gate (re-rendered `sync-check`), and the lefthook job (re-rendered frame; an edited `lefthook.yml` goes through keep / take / merge, ADR-0003); deletes this worktree's cache file; keeps `docs/code-map.md` and says so. Answers stay (ADR-0019).

## Acceptance tests (implementation PRs)

- Stale map: a new directory, a removed directory, an edited front-matter declaration and a hand edit inside a generated block each fail `check` with the repair command; `update` fixes them; adding a file to an existing directory does not fail.
- Broken references: missing `entry` / `tests` path, glob matching nothing, unknown `relates`, missing ADR, broken relative link.
- New, renamed, deleted files: index reflects each; rename hint when the hash matches; uncovered new top-level file fails.
- Dirty working trees: uncommitted edits, untracked non-ignored files and deleted tracked files are seen; ignored files are not.
- Branch and worktree changes: `git switch` to a branch with other directories, then `check` / `show` match that branch without a hook; two worktrees of one repo get two cache keys and do not affect each other.
- Exclusions: `.env`, a key file, `node_modules/`, a symlink to a file outside the project and a symlinked directory are never opened (spy on `open`) and never listed; `docs/code-map.md` as a symlink is refused.
- Determinism: two runs on different temp paths give identical `docs/code-map.md` bytes; `check` writes nothing (tree and cache unchanged).
- Preservation: maintained text, front matter and unknown headings stay byte for byte after `update`; malformed markers abort without writing; a concurrent edit during `update` aborts.
- Concurrency: two parallel `update` / `show` runs leave a valid cache and an intact map.
- Without GitHub and without a watcher: Quick + `yaw add code-map`, no `github` / `ci` / `git-hooks`, works fully; no watcher process exists.
- Hooks: no hook registered; `AGENTS.md` for Full (solo and team, both profiles) ≤ 80 lines.
- Removal: files, fragments, gate and lefthook job gone; `docs/code-map.md` kept; edited `lefthook.yml` goes through keep / take / merge; re-add asks no questions and keeps the existing map.

## Consequences

- `docs/code-map.md` costs a review step on structural changes; the pre-commit hook makes a commit that adds a top-level directory fail until the map is updated, and untracked, non-ignored scratch directories fail `just check` until ignored or excluded.
- The map is coarse by design (directories and declarations); finding a symbol still needs search. Symbol extraction is later.
- The pre-commit hook and `just check` see the working tree, not the commit; a map updated but not staged passes locally and fails in CI.
- Caches of deleted worktrees remain in `~/.yaw/cache/code-map/` until removed by hand (small JSON files).
- The `git-hooks` `AGENTS.md` block shrinks to one line to keep Full within 80 lines.

## Alternatives considered

- Cache under `.yaw/cache/` with an ignore entry: rejected (see above).
- Lock file for concurrent refresh: rejected; temp + rename plus a compare before rename covers the map, the cache needs no exclusivity.
- Separate CI job: rejected (ruleset job-name contract; `just check` already runs).
- `pre-push` lefthook job: rejected for now (duplicate top-level key with `team` in `lines` composition).
- Listing every file or file counts in `docs/code-map.md`: rejected (churn on every added file; the full list lives in the cache and `show`).
- A SessionStart hook that warms the cache: rejected (not needed for correctness; zero hooks is simpler).
