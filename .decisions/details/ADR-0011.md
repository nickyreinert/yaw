# ADR-0011: Shared retrieval engine in `core/lib/` and a Unicode-aware tokenizer

- Status: Proposed
- Date: 2026-10-21
- Issue: #56 (Y-5.6)
- Resolves: M1, M2 (`docs/build/plan.md` §1.5)

## Context

The governance blueprint (R E2, K1, K2) ships the retrieval code inside the decision journal and tokenizes with `[a-z0-9]+`. Two problems:

- **M1.** Doc 12 §1 says all three memory stores (decision journal, global knowledge, session registry) use "the same retrieval code", doc 11 §1 keeps a topic vector with "the same code as the decision journal", doc 13 §3 compares prompts by local embedding. Code under `modules/decisions/lib/` cannot be shared by `sessions` (Y-5.7) or `comfort` (Y-5.8) without making them depend on `decisions`.
- **M2.** The ASCII tokenizer splits German words at every umlaut or ß ("Größe" → `gr`, `e`; "Schlüssel" → `schl`, `ssel`), while German is a common chat language (doc 03 0.2). Taxonomy keywords with umlauts could never match.

## Decision

### Where the engine lives (M1)

- `core/lib/retrieval.js` holds everything that does not know about a store: `normalise`, `tokenize`, `embed`, `cosine`, `classify` (taxonomy keywords), `globToRegExp` / `scopeMatches` (path-aware recall), and the ranking pipeline `retrieve()`. Pure functions: no file I/O, no network, deterministic.
- Store code stays with its module: record format, index, IDs, CLI and hooks of the journal are in `modules/decisions/lib/` (doc 04's "logic in kit `modules/decisions/lib/`" applies to the journal, not to the engine). Y-5.7 (`yaw sessions find`) and later the knowledge store and tier-1 evaluation import the engine from `core/lib/`.

### Tokenizer and embedding (M2)

- Normalise with `String.prototype.normalize('NFKC')` and `toLowerCase()` (locale-independent).
- Tokens are runs of `\p{L}\p{N}` (letters and digits of any script); tokens of one code point are dropped. Hyphens and punctuation split ("Hook-Dispatcher" → `hook`, `dispatcher`).
- Before embedding, a short list of English and German function words (`the`, `to`, `der`, `für`, ...) is dropped (`terms()`); classification keeps every token. On the eval set (14 prompts against this repository's journal) this lowered the mean similarity of unrelated records from 0.07 to 0.01 and moved the expected record from mean rank 3.4 to 2.5; more dimensions (1024, 2048) did not help. No stemming and no transliteration (`ä` stays `ä`, not `ae`): the character trigrams already carry inflection ("Migrationen" ~ "migration").
- Embedding: the blueprint's 384-dimension signed feature hashing (FNV-1a; words weight 2, character trigrams 0.25, word bigrams 1; L2-normalised) over the terms, with trigrams over **code points** instead of UTF-16 units. Model tag **`local-hash-ngram-v2`** (v1 is the ASCII original). Vectors are stored rounded to four decimals (smaller index, stable diffs; cosine is unaffected at this precision).
- A change of tokenizer or features is a new model tag; `yaw decisions check` then fails until `yaw decisions rebuild` (the index must equal a rebuild).

### Classification

- A taxonomy keyword hits a prompt token when it is equal, when the token starts with a keyword of at least 4 code points (inflection: "migrationen", "hooks") or ends with one of at least 5 (German compounds: "datenbankmigration"). A keyword of several words ("forward-only") needs all of them. Score = number of keywords hit; ties are ordered by name.
- The seed taxonomy of the module carries English and German keywords, so a German prompt classifies even against English records.

### Pipeline (blueprint E4 with the upgrades of doc 04 / R N)

1. Classify the text; no pair and no scope match → nothing (absence stays visible).
2. Decisions: the best pair, plus the second pair when its score is equal (N3, ties only). Notices: every matched pair. `superseded` and `deprecated` entries are never returned (D2, N4).
3. Rank: cosine ≥ 0.12 (threshold kept), score = cosine × importance weight (critical 1.5, high 1.2, normal 1.0, low 0.8).
4. Always included: `critical` entries of a matched pair (D2); entries whose `scope` glob matches a given path (F4, N6); with `allCritical` (the task-start recall) every critical entry (N2).
5. A best pair whose decisions all stay below the threshold still yields its best-ranked decision (reason `category`). The blueprint lets the taxonomy do the heavy lifting and the vector only rank inside the pair (E1); without this a German prompt against English records finds the pair but no record.
6. Entries without a vector, or with a vector of another model, fall back to word overlap with their summary (E4 legacy fallback).

Each hit carries `reason`: `match`, `critical`, `scope` or `category`.

## Consequences

- One engine for decisions now and for sessions, knowledge and evaluation later; none of them depends on the `decisions` module.
- German (and any other script) tokenizes correctly; cross-language recall relies on bilingual taxonomy keywords and the category fallback, not on the vector. A semantic embedding model (N1) stays possible through `embeddingModel`.
- Retrieval quality is measured by an eval set in the tests (N5): prompts in English and German against this repository's journal, plus a fixture journal with German records.
