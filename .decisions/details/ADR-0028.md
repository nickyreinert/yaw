# ADR-0028: `decisions` module (ADR + notice journal, local recall)

- Status: Proposed
- Date: 2026-10-21
- Issue: #56 (Y-5.6)
- Resolves: implementation details of doc 04 (`decisions`), doc 12 §1–2 and the governance blueprint sections D, E, F, K, H4 (B rule 10); applies ADR-0010 (ID scheme), ADR-0011 (engine), BD7 (move of YAW's ADRs), BD9 / ADR-0007 and BUILD.md rule 5 as extended by the user (critical decisions at SessionStart, count chosen by the user)

## Decision

### Files in `.decisions/`

| Path | Owner | Notes |
|---|---|---|
| `taxonomy.json` | module, managed | seeded with 7 categories (Product, Architecture, Data, Delivery, Security, Operations, Governance), English and German keywords; changed through `yaw decisions taxonomy add` (BD2), so it usually becomes an edited file that `yaw update` keeps |
| `decisions.index.json` | module, managed | derived from the records; empty skeleton at install |
| `ADR-*.md`, `NOTICE-*.md` | user data | the truth; never written by `update`, never removed by `remove` |
| `details/*.md` | user data | optional detail docs (doc 12 §2), linked, never shown by recall |

### Record format (blueprint D4 plus the D2 fields of doc 04)

```markdown
# ADR-0007: Use forward-only migrations

- **Date:** 2026-10-12
- **Category:** Data / Storage
- **Status:** Accepted                    (notices: - **Kind:** security | business-logic | privacy)
- **Importance:** high                    (critical | high | normal | low; default normal)
- **Supersedes:** ADR-0003                (optional; also Superseded by, Scope, Review by, Tags)

## Context
## Decision                               (notices: ## Consideration)
## Consequences                           (decisions only)
## References                             (optional: - detail|spec|code|issue|commit|session: value)
```

- The summary is the title. Metadata lines may be bold or plain (`- Status: Accepted`), so hand-written records parse. Statuses: proposed, accepted, provisional, superseded, deprecated (notices default to accepted). Code references are `path#symbol`, never line numbers.
- The parser rejects: a heading whose ID differs from the file name, a missing or malformed date or category, an unknown status, importance or kind, missing sections, unknown reference types.

### Index

- `{ version: 2, model: "local-hash-ngram-v2", dimensions: 384, entries: [...] }`; an entry holds `id, type, kind, file, date, category, subcategory, summary, status, importance, supersedes, supersededBy, scope, reviewBy, tags, refs, embeddingModel, embedding`. The blueprint's `timestamp` is `date` (records carry dates); taxonomy `keywords` are not copied (classification happens at query time).
- Everything in it is derived from the Markdown by one function (`embeddingText` = summary + context + decision or consideration, blueprint N10), so `record` and `rebuild` cannot produce different vectors. `yaw decisions check` requires the index to equal a fresh rebuild byte for byte: a hand edit without `rebuild` fails `just check`.

### IDs (ADR-0010, R D5, N11)

- Solo: `ADR-NNNN` / `NOTICE-NNNN`, next = highest number in the records **and** the index + 1, so an ID is never reused. Team mode (`idea.team` not `solo`): `ADR-<issue>-<n>`, the issue from `--issue` or the branch name `<type>/<n>-<slug>`.
- `check` fails on duplicates, also across spellings (`ADR-7.md` next to `ADR-0007.md` is not a valid name; `ADR-00007` and `ADR-0007` collide), on records that name an unknown taxonomy pair or an unknown superseded record, and on an index that is not a rebuild. It warns on dead path references and passed review dates. It runs in `just check` (below).

### `yaw decisions` (blueprint K3, K4; `just decisions ...`)

- `record` (ADR or `--type notice`), `query --text` (JSON `{ id, file, similarity, score, reason }`), `recall "<task>" [--path f]` (the text the agent reads), `list`, `rebuild`, `check`, `taxonomy [add "C / S" --keywords "..."]`, `seed`.
- Arguments go through `parseArgs` in strict mode (N12): a value that starts with `--` is an error. Validation as in K4: unknown taxonomy pair (the message names `taxonomy add` as the deliberate act), empty summary or context, decision + consequences for ADRs, kind + consideration for notices, unknown `--type`; multi-line text may not start a line with `#`/`##` (it would end a section). Writes are atomic (temp file + rename); `--supersedes X` marks X as superseded by the new record.
- `seed` records the setup proposal (`answers.yaml#proposal`, its rejected alternatives in the Context) as one provisional ADR in `Architecture / Stack` with a review date 90 days ahead, once (tag `proposal`). This is ADR-0009's "creates provisional ADRs when `decisions` is added", made an explicit command: `yaw add` writes only module files, and records are user data.

### Recall: critical decisions at session start, full records on demand (BUILD.md rule 5, ADR-0007)

The blueprint's recall hook (F2) injects records on every prompt; YAW does not. BUILD.md rule 5 allows exactly two model-visible outputs: the active task at `SessionStart`, and the critical decisions at `SessionStart`, one short line each (ID and title), no record bodies. This module uses the second and nothing else.

**User choice (design update, replaces the earlier fixed cap of 5).** The number of critical decisions injected at `SessionStart` is chosen by the user. The default is 0: nothing is injected. The maximum is 10; a larger value is rejected with a clear message ("too many: the maximum is 10"). The dispatcher's policy cap of ADR-0007 (lines and characters per module) still applies on top. The choice is stored in the module's configuration (an interview question of the `decisions` module; implementation follows).

**Agent support.** Copilot does not support `SessionStart` context (`support: none` on the hook). The user should know this: with Copilot, critical decisions only reach the model through the generated file below and `just decisions recall`.

**One generated file, no duplication.**

- `.decisions/CRITICAL.md` is generated from the index (records with `importance: critical`, excluding superseded and deprecated ones): one line `ADR-NNNN <title>` each, titles clipped and cleaned as before, no bodies.
- `AGENTS.md` contains one reference line to this file (for example "Read `.decisions/CRITICAL.md` before you start"), never the decision text itself.
- The `SessionStart` hook (Claude, Codex) reads the same file and injects its lines, up to the user's number. Copilot and other agents without `SessionStart` support read the file because `AGENTS.md` points to it.
- Duplication concern: decision text copied into `AGENTS.md` would drift from the records and cost tokens in every session of every agent. Mitigation: `AGENTS.md` holds only the reference; the file is derived from the index; `yaw decisions check` (part of `just check`) fails when `CRITICAL.md` differs from a fresh generation, like the index check. `rebuild` regenerates it.

**Hooks and recall.**

1. **`session-start-critical` hook, `SessionStart`, kind `context`, `tokenCost: low`.** Reads `.decisions/CRITICAL.md`, returns once per session a header line plus the lines up to the user's number, nothing when the number is 0 or no decision is critical. Claude and Codex get it as `additionalContext` (policy cap ADR-0007: 10 lines, 1000 characters per module). No record bodies.
2. **Fallback and full records: task-start recall by the agent.** The module's `AGENTS.md` lines tell every agent to run `just decisions recall "<task>"` (with `--path` for files it will change) and to cite the IDs. The output is a tool result the agent asked for: matching records verbatim, at most five, detail docs only named; critical records are always included. This is the fallback when a hook does not run (Copilot, untrusted Codex hooks, missing kit) and the only way to read record bodies.
3. **`recall` hook, `UserPromptSubmit`, kind `comfort`, `tokenCost: none`.** Returns a synchronous `systemMessage` for the user naming up to three matching records. Silent when nothing matches; never `additionalContext`. Claude and Codex show it; Copilot drops `userPromptSubmitted` output (`support: none`).
4. **No `PreToolUse` path hook.** Path-aware recall (F4, N6) is `--path` on `recall` and `query`.

The prompt hook needs the prompt: the dispatcher passes `prompt` to handlers in memory; it never enters the normalised event or a log (ADR-0018). Both hooks read only committed files (no record files, no network). Any error ends in exit 0 and no output (dispatcher, fail open).

### Storage: plain text plus `yaw.db` (design update, not implemented yet)

- **Plain text is the source.** `.decisions/*.md` stays the truth and is committed.
- **`yaw.db` is the discovery index.** A `decisions` table in the embedded database (`~/.yaw/yaw.db`, next to the sessions registry) holds one row per record: `id, project, file, title, summary, category, subcategory, status, importance, date, supersedes, session, embeddingModel, embedding`. The row is derived from the record, so a rebuild reproduces it. (This extends BD3, which limits `yaw.db` to the registry tables; the user has approved this extension; recorded in BUILD.md BD3.)
- **Every stored record comes with its embedded fields.** No record exists in `.decisions/` without the fields needed for retrieval; `record` and `rebuild` write both in one step, and `check` fails on a record without a matching row or fields.
- **What is embedded (recommendation).** Embed title + short summary + category path (`Category / Subcategory`) for each record. The full detail body is not embedded in the index; it is shown only on retrieval (the short record verbatim, the detail doc named).
  - Why: small and precise vectors; the title and summary carry the topic, the category path adds a stable hook for the filter and for German/English keywords; long bodies dilute a lexical hash embedding with boilerplate and make the index and the rebuild larger and slower.
  - If recall turns out poor, a longer embedding (context + decision, as the current `embeddingText`, or the full body) can be added later without changing the format: `embeddingModel` identifies the recipe and `rebuild` regenerates every vector.
- **Category tree.** Reuse `taxonomy.json` where it already has the categories; add one. Proposed tree (YAW's own taxonomy today, plus UI):
  - Architecture: Formats, Rendering, CLI
  - Agents: Hooks, Skills
  - Modules: Catalogue, Workflow
  - Memory: Decisions, Sessions
  - Security: Guards
  - Delivery: Platform
  - Governance: Scope, Repository
  - UI: Design (new; for the phase-2 `ui-design` module)

  Mapping to the common names: Process = Governance / Modules (Workflow); Tooling = Delivery and Agents; Memory and Sessions = Memory; UI is new. The module's seed taxonomy for user projects (Product, Architecture, Data, Delivery, Security, Operations, Governance) is separate and unchanged, except that a UI category is offered when the project has a UI.

### Project name (design update, not implemented yet)

- `yaw init` asks one question for the project name; the default is the folder name. The answer is stored in the manifest. This is a question in the init interview and therefore user-visible (B rule 10).
- Every decision row in `yaw.db` carries the project name (the sessions rows carry it too, ADR-0029).
- `yaw decisions` accepts the filters `--project`, `--model` (the embedding model) and `--session` (decisions cited by or recorded in a session), on `list`, `query` and `recall`; `yaw sessions` accepts the same filters.

### `just check` (gates)

- `module.yaml#outputs.gates` (in the schema since step 1, unused so far) now means: recipes that `just check` runs. `core`'s justfile frame renders them as dependencies of `sync-check`, which every profile's `check` already runs (ADR-0012, ADR-0020): `sync-check: decisions-check`. With no gate module the frame is byte-identical to before.
- `decisions-check` runs `yaw decisions check`; without the kit it prints a note and passes, like `sync-check`. CI installs the kit (BD10), so CI checks the journal.

### Path safety

Every path is checked before any file I/O, and no component of `.decisions/…` may be a symbolic link, even one that stays inside the project. Record files are only addressed as `.decisions/<ID>.md` with a validated ID, never through a path read from a record or from the index. Reference paths from records are only checked for existence with `lstat` (no read), and a reference through a link or into `.git` is reported. Agent-supplied `--path` values are only matched against `scope` globs, never opened.

### Removal and footprint

- `yaw remove decisions` deletes the unedited managed files (an edited taxonomy or a filled index is kept as "yours", as for every managed file) and the module's fragments: the `AGENTS.md` block, the `justfile` import and the `sync-check` dependency, the hook registrations (both hooks). Records and detail docs stay. The module has no questions, so `answers.yaml` is not touched.
- Standard and Full get the module by default (doc 04); Quick does not.

### This repository (BD7)

- `docs/adr/NNNN-*.md` moved with `git mv` to `.decisions/details/ADR-NNNN.md` (history kept); each got a short record `.decisions/ADR-NNNN.md` that links its detail doc. ADR-0016 is marked superseded by ADR-0014 (ADR-0014 said so once accepted). The taxonomy is YAW's own (Architecture, Agents, Modules, Memory, Security, Delivery, Governance). New ADRs are written with `just decisions record` (plus a detail doc when the rationale is long).

### Not in this step

- Semantic embeddings (N1), a PR check that descriptions cite IDs (N7), a periodic review report (N13; `check` warns on passed dates), blocking edits of accepted records, the global knowledge store and `/remember` (phase 2).

## Consequences

- Model tokens per session: the critical-decision lines the user chose (default none); record bodies cost tokens only when the agent runs recall. The user sees on every matching prompt which records should be cited.
- Agents that skip the `AGENTS.md` rule get only the critical lines the user chose (Claude, Codex) or nothing (Copilot, unless it follows the `CRITICAL.md` reference) (blueprint N7); the user-visible note makes a missing citation noticeable.
- A record edited by hand needs `just decisions rebuild` before `just check` passes.
- Design update (this PR, docs only): `CRITICAL.md`, the user-chosen count, the `decisions` table, the embedding recipe, the category tree and the project name are specified here and not implemented; follow-up work is listed in `docs/build/plan.md` (Y-5.6).
