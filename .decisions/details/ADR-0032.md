# ADR-0032: Setup depth: Quick and Full

- Status: Proposed
- Date: 2026-10-21
- Issue: Y-5.10 (#134)
- Amends: ADR-0009 (Standard and Full contents, comfort questions, "Full = Standard + F questions"); its terminology, Quick question rule, footprint, ADRs without `decisions` and the `AGENTS.md` budget stay Accepted
- References without changing their status: ADR-0013 (Proposed), ADR-0030 (Proposed), ADR-0020, ADR-0023, ADR-0031

## Context

Step 5.10 (BUILD.md) asks for two setup choices, Quick Start and Full Setup, where the mode controls generated output, not only the questions shown. An audit of `origin/main` (`f74a2ad`) found:

- BD5 (BUILD.md) lists five Quick modules; ADR-0009 lists six (`security` added by the user).
- Standard and Full select the same modules (every `module.yaml#default` has the same value for both). The only F question is `team.session-context` (Y-5.9), whose default is the Standard behaviour, so Full produces the same output as Standard.
- Doc 02 §2 makes Standard the default and says "Mode changes how many questions are shown, never what is possible".
- Doc 04 §1: `sessions` depends on `tasks` in the doc but on `core` in `module.yaml`; comfort "asked" one by one in Full is not built (comfort has one multi-select question, `user.comfort`, mode S); phase-2 modules (`quality-code`, `business-logic`, `privacy`, `dashboard`, …) are ticked under Standard.
- Doc 03 question 1.3 (prototype / MVP / long-lived product) points to "preset" without a mapping.
- Rendering every Full module for a solo `node-cli` or `python-cli` project fails today: `AGENTS.md would have 83 lines, the budget is 80`. A team project renders 79 lines because `communication` writes nothing there (ADR-0013). The same happens with `mode: standard`.

## Decision (decided by the user)

### Two choices

| Choice | For | Modules (phase 1) | Questions asked |
|---|---|---|---|
| **Quick** | Prototypes, MVPs, short projects: the essential baseline | `core`, `communication`, `standards`, `devenv`, `tasks`, `security` (minimal) | Q of the enabled modules |
| **Full** | Maintained products | Quick + `git-hooks`, `decisions`, `sessions`, `comfort`; `github` and `ci` unless the user does not use GitHub; `team` when the project is a team | Q, S and F of the enabled modules |

- **Standard is merged into Full.** New projects are offered Quick and Full only. `standard` stays a valid value in `answers.yaml#mode`, `manifest.json#preset` and the schema; it is never rewritten and its output is unchanged: it selects by `module.yaml#default.standard` (kept as it is today; a module added later copies its Full value there) and asks Q and S questions, as before. A test proves a `standard` answers file renders byte for byte what it rendered before this change.
- **Relevance in Full (output, not only questions):**
  - `github` and `ci` are on by default. They are off only when the user says they do not use GitHub: doc 03 question 10.2 ("Use GitHub for the repo?"), built as a boolean with default yes, asked in Full (moved from Q to S, since no Quick module uses it; ADR-0009 P2). A team project implies GitHub (`team` depends on `github`, ADR-0010 forces GitHub tasks), so 10.2 is not asked there. Without GitHub, `tasks.mode` is `local` and is not asked.
  - `git-hooks`, `decisions`, `sessions` and `comfort` are always on in Full (`git-hooks` needs no GitHub).
  - `team` only when 1.5 is team (unchanged, ADR-0031).
  - Phase-2 and phase-3 modules are in no mode (labelled `later`).
- **Comfort in Full** uses the existing multi-select `user.comfort` (default hygiene + status line, ADR-0030). There are no per-item questions in phase 1.

### Hooks and skills per mode

Hooks stay registered per module: enabling a module registers all its hooks, removing it removes them. There is no per-hook selection and no per-hook schema field. The table is the contract the hook/skill table test checks against the generated adapter files (Claude, Codex, Copilot per each hook's `agents` support).

| Module | Quick | Full | Agent hooks (event, kind) | Skills | Other agent config |
|---|:-:|:-:|---|---|---|
| `core` | ✔ | ✔ | – | – | – |
| `communication` | ✔ | ✔ | – | – | Claude output style when non-default; nothing in team projects (ADR-0013) |
| `standards` | ✔ | ✔ | – | – | – |
| `devenv` | ✔ | ✔ | – | – | – |
| `tasks` | ✔ | ✔ | `stop-resume-point` (Stop, comfort); `session-start-task` (SessionStart, context, low) | – | – |
| `security` | ✔ | ✔ | `guard-secret-read` (PreToolUse, guard); `guard-destructive` (PreToolUse, guard) | – | Claude `permissions.deny` |
| `git-hooks` | – | ✔ | – (git hooks via lefthook: secrets, format, lint) | – | – |
| `github` | – | ✔ unless no GitHub | – | – | Claude `permissions.ask` for guarded commands (ADR-0027) |
| `ci` | – | ✔ unless no GitHub | – | – | – |
| `decisions` | – | ✔ | `recall` (UserPromptSubmit, comfort); `session-start-critical` (SessionStart, context, low; prints nothing at the default count 0) | – | – |
| `sessions` | – | ✔ | `register` (SessionStart, evaluation); `touch` (Stop, evaluation); `end` (SessionEnd, evaluation) | `handoff` | – |
| `comfort` | – | ✔ | `prompt` (UserPromptSubmit, comfort); `stop` (Stop, comfort); `notification` (Notification, comfort); `failure` (StopFailure, comfort); `check-ok` (PostToolUse, evaluation); `check-fail` (PostToolUseFailure, evaluation) | – | Claude `statusLine` (solo projects only, ADR-0030) |

Quick therefore registers four agent hooks (two context/comfort from `tasks`, two guards from `security`) and no skill.

### Quick is a baseline; the mode is the starting depth

- A Quick project grows with `yaw add <module>` (ADR-0023: only that module's questions, earlier answers as defaults, dependencies refused, not installed). Adding a module never changes the mode.
- `answers.yaml#mode` and `manifest.json#preset` record the depth chosen at `yaw init`. They are not the project's current state: commands that need to know what is installed (`yaw status`, `yaw agents`, `yaw doctor`, hooks) read `manifest.json#modules`, never the mode.
- As before (ADR-0023), a module added to a Quick project asks only its Q questions; its S and F questions take their defaults.

### `AGENTS.md` budget in Full

The 80-line limit (`AGENTS_MAX_LINES`, ADR-0009) applies to Full, the largest selection. The render already fails above it. The implementation must add a test that renders the largest Full selection (solo, with GitHub, every phase-1 Full module) for each built profile and asserts `AGENTS.md` has at most 80 lines; a team variant is checked too. Since the solo case is 83 lines on `main`, the implementation shortens module `agentsMd` blocks (or the core frame) first; detail moves to `docs/spec/` or a skill (doc 04 §2).

### Question 1.3

Doc 03 question 1.3 maps to the choice: prototype → Quick, MVP → Quick, long-lived product → Full. The answer pre-selects the choice; the user can change it. This is built with the full interview (step 7), not in step 5.10. Until then interactive `yaw init` stays Quick and `yaw init --answers` takes the file's mode.

## Not in this ADR

- Code: selection changes (`module.yaml#default.full` for `github` / `ci`, question 10.2, the `standard` alias), the hook/skill table test, the `yaw add` expansion test and the `AGENTS.md` fixes follow in the next 5.10 PRs.
- How step 7 presents the two choices in the CLI and the form.

## Consequences

- ADR-0009 is amended, not superseded: its contents table and "Full = Standard + F questions" are replaced by the table above. BD5, docs 02, 03, 04 and `docs/build/plan.md` follow in the same PR.
- An existing project with `mode: standard` keeps its modules and files; `yaw update` does not change the mode.
- ADR-0013 and ADR-0030 are still Proposed; this ADR relies on them (team projects commit no personal style; comfort settings and status line) without changing their status.
