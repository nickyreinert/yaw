# ADR-0029: `sessions` module: registry, commit trailer, `/handoff`

- Status: Proposed
- Date: 2026-10-21
- Issue: Y-5.7 (#57)
- Resolves: implementation details of doc 12 §4 and doc 11 §1 (B rule 10); applies BD3 (registry tables only), ADR-0018 (registry storage), ADR-0007 / BUILD.md rule 5 (token-free hooks), ADR-0028 (path-safety lessons)

## Decision

### Registry

- Tables `sessions` and `session_links` of `~/.yaw/yaw.db` (`$YAW_HOME/yaw.db`), unchanged: no migration, no `summary` column. Link kinds: `task` (`T-012`, `#34`), `commit` (12-character hash), `file` (project-relative). The `decision` kind exists in the schema; nothing fills it yet (IDs cited in a session would need the transcript, which this module never reads).
- Session id = `<agent>:<native id>`; the native id must match `[A-Za-z0-9][A-Za-z0-9._-]{0,127}`, otherwise the session is not registered. Copilot is told apart from Claude by its payload (ADR-0021), so its id is `copilot:<id>`.
- The registry is global, outside every repository, so it is never committed. `.yaw/sessions/` (doc 12's project folder, used only for an opt-in export of titles and links) is added to `.gitignore` by the module so that it cannot be committed by accident.
- The database file must be a regular file (a symbolic link is refused); the directory is set to `0700` only when it was just created, or is a real directory (not a link) named `.yaw` that the user owns; a link, a foreign directory or a `YAW_HOME` pointing elsewhere (e.g. `$HOME`) is never chmod-ed, and a failed chmod never fails the registry. `busy_timeout` 3 s because several sessions write the same file.
- Removing the module leaves `~/.yaw/yaw.db` alone: it is user data outside the project and other projects use it.

### Storage and project name (design update, not implemented yet)

- Sessions are stored in the embedded database (`yaw.db`, tables `sessions` and `session_links`); the decisions module stores its records as plain text in `.decisions/` and as rows of a `decisions` table in the same database (plain text is the source, the database is the index for discovery; ADR-0028).
- `yaw init` asks one question for the project name; the default is the folder name; the answer is stored in the manifest. This is a question in the init interview, so it is user-visible (B rule 10).
- Every `sessions` row carries the project name (a new column; it replaces the project path as the display and filter key, the path stays for `resume`). Decision rows carry it too.
- Filters, on `yaw sessions list/find/for` and on `yaw decisions list/query/recall`: `--project <name>`, `--model <agent model or embedding model>`, `--session <id>`. `--all` stays the switch for every project; `--project` selects one by name.
- Schema change: a new column and a migration of `yaw.db`; BD3 and ADR-0015 limited `yaw.db` to the registry tables, so the extension is recorded here. The user has approved the project-name column.
- Not implemented in this PR: it only updates the design. Implementation follows (`docs/build/plan.md`, Y-5.7).

### Hooks (all `evaluation`: no output, ever)

- `register` (SessionStart), `touch` (Stop), `end` (SessionEnd, Claude only). Output is dropped by the dispatcher whatever the handler returns; tests assert empty stdout and stderr for every fixture of every agent, also through the real shim.
- A Stop or SessionEnd without a SessionStart still creates the row (module added mid-session, Codex trust not yet given); its `started` is then the time of that Stop, so the commit scan starts there.
- The transcript path comes from the payload (`transcript_path`), is handed to handlers in memory like the prompt (the dispatcher change is one line) and is stored only when it is an absolute path without control characters, at most 1024 characters. The module never opens it.
- Stop and SessionEnd also set `ended`, refresh the branch task link, and link the commits whose message carries `Agent-Session: <id>` (exact match through git trailers; HEAD's history only, since the session started, at most 100, already linked commits are not diffed again, because this runs on every Stop) and the files they touched (at most 50 per session in total, only paths the kit's own path check accepts). Commits come from the trailer, not from a start/end HEAD range, because the registry has no column for the start HEAD and a trailer is exact when sessions overlap.

### Title

- From the active task of `TASKS.md`: `T-012 Online invite flow`; the task of the current branch wins when it is active. Set once (`COALESCE`), so a handoff title or a title renamed in the database is never overwritten (doc 12: "only if no custom title exists").
- Registry only. Returning `sessionTitle` to Claude Code would need a new output channel in `policy.js`; it is left for a later issue together with `yaw session rename`.

### Trailer

- `yaw gh commit` appends `Agent-Session: <id>` as its own final paragraph (so git sees a pure trailer block). `core/cli/gh.js` passes a `sessionTrailer` function when the sessions module is enabled; the github module does not import the sessions module.
- Which session is "current": `$YAW_SESSION` when set and well-formed, else the project's session with the latest `ended`/`started` within 4 hours. None, an error or an unreadable registry means no trailer; a commit never fails because of the registry. Two sessions working in one project at the same time can get each other's id (set `YAW_SESSION` to be exact); Claude's `CLAUDE_ENV_FILE` could export it, left for later.
- Plain `git commit` carries no trailer; `yaw sessions current` prints the id for people who want to add it by hand.

### CLI

- `yaw sessions find "<words>"`: the shared embedding of ADR-0011 over title, branch and the task / decision links (cosine at least the retrieval threshold), an exact id or link match scores 1; at most 10 hits. `for <ref>`: task (`T-012`, `#34`, `34`), decision (`ADR-0004`), commit (7 to 64 hex, prefix match) or a project-relative file; anything else is a usage error. Both search this project only; `--all` searches every project.
- `resume <id>` takes the full id or at least 4 characters of it and prints `cd '<project>' && <agent command>`. It does not run it: an interactive agent cannot be started from a hook-free CLI call anyway, and the registry is not trusted. The command is rebuilt from the agent and the validated native id; the stored `resume` text is ignored. A row with an unknown agent or a control character in its project path is reported as damaged.
- `list`, `current`, `handoff [--title t] [--agent a] [--session id]`: `handoff` records the current session (title, `ended`, links). Without a registered session (Copilot, hooks not trusted) `--agent` creates `<agent>:handoff-<UTC time>`.
- Everything printed from the registry or from `TASKS.md` has control characters removed (terminal escapes).

### `/handoff` skill

- `modules/sessions/skills/handoff/SKILL.md`, copied to `.agents/skills/` and (Claude) `.claude/skills/` (ADR-0012). The agent logs the resume point with `just task log … --resume …`, runs `just sessions handoff --title …` and tells the user it is safe to `/clear`. The re-injection after `/clear` is the tasks module's SessionStart hook; this module adds no model-visible output.

### Agents

| | Claude | Codex | Copilot |
|---|---|---|---|
| registry hooks | SessionStart, Stop, SessionEnd (native) | SessionStart, Stop (native, hooks must be trusted) | via `.claude/settings.json`, payloads confirmed by fixtures only (partial) |
| `/handoff`, trailer, CLI | yes | yes | yes |

### Not in this step (later issues)

Decisions cited in a session, `pr` back-link and the ADR / task-journal back-links, `yaw session rename`, native `sessionTitle`, exporting titles and links to `.yaw/sessions/`, a `summary` column, an exact current-session channel (`CLAUDE_ENV_FILE`).

## Consequences

- No new runtime dependency; no schema change in the shipped code (the project-name column above is design only); one-line dispatcher change (`transcript`).
- The registry holds paths and ids, never content; its text is cleaned before display.
