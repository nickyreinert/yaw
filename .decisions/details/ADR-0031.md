# ADR-0031: `team` module (team mode)

- Status: Proposed
- Date: 2026-10-21
- Issue: Y-5.9 (#59)
- Resolves: implementation details of doc 14 §2–§3 (B rule 10); applies BD3 (pr-policy = "PR links an open issue"), BUILD.md rule 5 / ADR-0007 (token-free hooks), ADR-0027 (guarded GitHub writes), ADR-0010 (`task start` in team mode was left to this step), ADR-0026 (lefthook)

## Decision

### One module

- Team mode is an interview answer; its enforcement is the module **`team`** (`modules/team/`), so it installs, shows in `yaw agents` and is removed like every other module. `default: { quick: false, standard: { team: true }, full: { team: true } }` (Quick has no `github` / `git-hooks`); `depends: [tasks, github, git-hooks]`.
- Outputs: a part of `lefthook.yml` (now a shared file owned by `git-hooks`, `lines` style; the git-hooks template is the frame, the team block sits between `# yaw:team` markers), `.lefthook/pre-push/yaw-default-branch.sh`, `.github/workflows/pr-policy.yml`, `just/team.just` (`just start`), its `AGENTS.md` block (3 lines), two SessionStart hooks. One question, `team.session-context` (boolean, Full only, default true).
- `.yaw/github.yaml` (github module) lists `pr-policy` in `rules.requiredChecks` while the team module is installed (template flag `teamModule`), so removal takes the required check away again.
- `rules.requireIssue` in `github.yaml` stays informational: the module is the switch.

### Security boundary and agent rules (decided by the user on PR #132)

- **The boundary is the GitHub ruleset plus `pr-policy` plus lefthook.** The ruleset (`just gh-protect`, ADR-0027) requires a pull request into the default branch, blocks force pushes and deletion, and has no bypass actors; `pr-policy` makes every pull request link an open issue of the repository; lefthook checks commit messages and refuses pushes to the default branch locally.
- **There is no agent-side command guard.** A first version had `PreToolUse` guards (edits off an issue branch, `git commit` / `git push` to the default branch, force pushes, `--no-verify`, `core.hooksPath` overrides, a live "diverged" lock). Review of PR #132 found ways around the shell-command parser; the user chose to drop it rather than keep extending it. The module registers no `PreToolUse` hook and denies nothing.
- The `AGENTS.md` rules (work on an issue branch via `just task start <#>`, `Refs #<n>`, no push to the default branch, no force push, no `--no-verify`, PRs link an open issue) are **guidance only**. An agent can break them locally; the ruleset and `pr-policy` stop the result at GitHub. So the boundary exists only once a person has applied the ruleset (`just gh-protect`); `just gh-protect --verify` checks it.
- Rulesets need GitHub Pro (or Team) for a private repository. On a free private repository GitHub refuses rulesets and branch protection (HTTP 403, seen on `nickyreinert/yaw` on 2026-10-21), so there the boundary is only `pr-policy` (reported, not required) and lefthook; `just gh-protect --verify` shows GitHub's error.
- **No lock flag.** Doc 14 §3's lock (deny edits until `just sync`) needs an agent-side guard, so phase 1 has none: a diverged or dirty branch is reported at session start as information only.

### Git hooks (lefthook)

- `commit-msg` (a `run` job): passes when a non-comment line has `#<n>` (`Refs #34`, `Closes #34`, `(#34)`); git's own `Merge …` / `Revert "…"` messages and `fixup!` / `squash!` / `amend!` pass. `{1}` is substituted raw by lefthook (checked with lefthook 2.2.2).
- `pre-push` is a **script** (`script:` + `runner: sh` + `use_stdin: true`), not a `run` job: lefthook skips `run` jobs on pre-push when the push brings no new files (`git push origin feat/34-x:main` after the branch was pushed), a script always runs (lefthook source, checked with 2.2.2). It refuses updating or deleting the default branch (`refs/remotes/<remote>/HEAD`, else main/master); creating it (remote sha all zeros: the first push of a new repository, `just gh-init`) passes.
- `--no-verify` bypasses both locally, as with every git hook; CI and the ruleset do not depend on them.

### `pr-policy` (CI)

- `.github/workflows/pr-policy.yml`, job `pr-policy` (the name is the ruleset contract), on `pull_request` (opened, edited, reopened, synchronize, ready_for_review). Never `pull_request_target`. `permissions: contents/issues/pull-requests: read`; no checkout, no third-party action, so nothing to pin. One `gh api graphql` call reads `closingIssuesReferences` and passes when at least one linked issue is open and belongs to this repository (`repository.nameWithOwner`, compared case-insensitively; BD3: nothing else in phase 1). The `--jq` filter is tested with the real `jq` on a recorded answer shape. Event data reaches the script only through `env` (no `${{ }}` inside `run`).
- GitHub fills `closingIssuesReferences` only for pull requests into the default branch; team-mode PRs target it. Linking under "Development" also counts; such a link triggers no event, so the check is re-run by hand.

### Rulesets (`just gh-protect`)

- Applying stays guarded (ADR-0027: plan, then a typed `y` on a terminal; no `--yes`). New: `yaw gh protect --verify` (`just gh-protect --verify`) reads the ruleset and compares it with `.yaw/github.yaml` (same comparison as after applying: default branch, pull request with N approvals, no force push (`non_fast_forward`), no deletion, required checks, and no bypass actors; a response without `bypass_actors` counts as a difference); it writes nothing and therefore needs no person. Missing or different → exit 1 with "a person runs: just gh-protect".
- `protect` refuses to require `pr-policy` while `.github/workflows/pr-policy.yml` is missing (a check nobody reports would block every PR), like the existing `quality-gate` rule.

### Session start (doc 14 §3)

- Two SessionStart hooks, no matcher (startup, resume, clear, compact; Codex's matcher translation would drop `clear`):
  - `session-sync` (kind `comfort`, user only): `git fetch --prune --quiet origin` (4 s limit, `GIT_TERMINAL_PROMPT=0`, SSH `BatchMode` unless the user set their own ssh command), then the policy: clean and behind and not ahead → `git -c core.hooksPath=/dev/null merge --ff-only <upstream>` (no git hook runs inside the session-start hook) (the default branch without tracking compares with `origin/<default>`); diverged → reported, nothing pulled (information only); dirty and behind → reported, not pulled; a feature branch behind `origin/<default>` → "N commits behind main: rebase or merge when it suits you (never automatic)"; on the default branch or a branch without an issue → "edits need an issue branch: just task start <#>". Then three `gh` reads at once (4 s limit each): my open issues (`--assignee @me`), PRs with `review-requested:@me`, my PRs with failing checks or requested changes. Issues are sorted by the `priority:` label, then the milestone due date; the `estimate:` label is shown. Returned as one `systemMessage` (Claude, Codex). Copilot gets no user message, so it runs no sync (`support: none`); `just start` is the fallback for every agent.
  - `session-issue` (kind `context`, `tokenCost: low`): one line, `Active issue: #34 "<title>" (branch feat/34-…).`: the active-task re-injection of BUILD.md rule 5. Local only (branch name plus the title from the cache); nothing on the default branch; off with `team.session-context: false`. Branch status, PR lists and phase rules (doc 14 §3.4) are **not** given to the model: rule 5 allows only the active task. Copilot gets it as `additionalContext`.
- **Cache (5 minutes):** `~/.yaw/cache/team-<sha256(project path)[:16]>.json`, `{ v, at, data }` with numbers, short cleaned strings and dates only. Within 5 minutes no `gh` call is made. Fetch failed → no `gh` call, the last result is shown as "offline, last sync YYYY-MM-DD HH:MM" (or "no earlier sync to show"); a failing `gh` → "GitHub not reachable (…), last sync …". Nothing throws into the session.
- **Path safety:** the home must be absolute (`YAW_HOME` or `HOME/.yaw`); the cache is opened with `O_NOFOLLOW` and must be a regular file under 512 KB; it is written to a new temporary file (`wx`, 0600) and renamed, never through a link (a link at the file or the folder is left alone). A hand-edited cache is cleaned like a `gh` answer (positive integer numbers, enum-checked priority / estimate / reasons, control and bidi characters removed, titles cut to 80 characters). Cache data is shown, never used as a path or a command. GitHub titles reach the model only through the one context line, cleaned and quoted.
- Hook time: fetch (4 s) and the parallel `gh` reads (4 s) stay inside the 10-second hook timeout. The handler is async; the dispatcher mutes stdout while it awaits (ADR-0007), which is harmless in `yaw hook` (one hook per process). Tests therefore run SessionStart through the real shim in a child process.
- `yaw session-start` (`just start`) prints the same lines in the terminal.

### `just task start <#>` in team mode (ADR-0010 left this to Y-5.9)

- After assigning the issue (tasks module), the CLI hands over to the team module (`io.startBranch`; tasks does not import team): already on the issue's branch → nothing; a local branch `<type>/<#>-…` exists → `git switch`; else the github module's `branch` verb creates `<type>/<#>-<slug of the title>` from the fresh `origin/<default>` (`fix/` for a `type:bug` label, `feat/` otherwise; slug `issue` when the title has no letters or digits). Project Status, worktree and session link stay later (#110).

## Not in this step

- `just sync` (rebase or merge per team ADR), Project fields (iteration, target date) and phase / freeze information at session start, Definition of Ready and branch-name rules in `pr-policy` (BD3: phase 2), a guard for raw `gh pr merge` (ADR-0027 ask rules cover it for Claude).

## Consequences

- A team project in Standard or Full gets the module; in Quick the dependency rule reports what is missing (`yaw add github`, `yaw add git-hooks`, then `yaw add team`).
- Removal deletes the team block of `lefthook.yml`, the script, the workflow, the recipe, the two SessionStart hooks and the `AGENTS.md` block, takes `pr-policy` out of `requiredChecks`, keeps the answer; the cache in `~/.yaw/cache/` is personal and left alone. Rulesets already applied on GitHub are not touched (as in ADR-0027); a person runs `just gh-protect` again.
- Copilot: it runs the SessionStart hooks of `.claude/settings.json` and gets the active-issue line as `additionalContext`; no session-start message (not verified live).
