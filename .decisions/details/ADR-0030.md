# ADR-0030: `comfort` module: hygiene, status line, notifications; personal configuration; last check status

- Status: Proposed
- Date: 2026-10-21
- Issue: Y-5.8 (#58)
- Resolves: M7 (comfort part), M8, M14 (B rule 10); applies ADR-0007 / BUILD.md rule 5 (token-free hooks), ADR-0013 (personal vs. committed), ADR-0028 and ADR-0029 (path-safety lessons)

## Context

Doc 11 describes three phase-1 comfort features. Three points are open: M7 (comfort settings are personal, but `.claude/settings.json` and `.yaw/config.yaml` are committed), M8 (the status line shows the "gate status of the last `just check`", which nothing stores; comfort leans on sessions and tasks) and M14 (hygiene "uncheckable" against ADR-0013).

## Decision

### Shape

- Module `comfort`, depends on `core` only; Standard and Full, not Quick. One question, `user.comfort` (multi: hygiene, status-line, notifications, cache-reminder as a greyed-out phase-2 choice), default hygiene + status line, scope user.
- Hooks, all synchronous and user-only (kind `comfort`: `systemMessage` for Claude and Codex, `terminalSequence` for Claude): `prompt` (UserPromptSubmit, hygiene), `stop` (Stop, "done"), `notification` (Notification, `permission_prompt|idle_prompt`, "needs input"), `failure` (StopFailure, "failed"). Two `evaluation` hooks print nothing: `check-ok` (PostToolUse, Bash) and `check-fail` (PostToolUseFailure, Bash). No `additionalContext` anywhere; the comfort module adds no model-visible output (tokenCost none). Tests run every hook against every recorded fixture of every agent.
- Agents: Claude native (all), Codex partial (hygiene and notifications as a `systemMessage`; no Notification / StopFailure event, no status line, no escape sequence), Copilot fallback (output of its prompt and stop hooks is dropped): an `AGENTS.md` line plus `yaw hygiene` by hand.
- The dispatcher hands one more short field to handlers, `notificationType` (a `[a-z_]` string), like `prompt` and `transcript`.

### Personal configuration (M7, ADR-0013)

- Personal settings are `~/.yaw/comfort.yaml` (`comfort.schema.json`): `features`, `hygiene` thresholds, `notify` (minutes, terminal sequence, ntfy). It lives in the user's home, so it cannot be committed; YAW reads it and never writes it, so the user's comments and the ntfy topic (a password) are left alone. This replaces doc 11's `.yaw/config.yaml` thresholds and `~/.yaw/notify.yaml`: the `hygiene` block leaves `config.schema.json` (project settings keep only `knowledge`), and one personal file replaces two. A per-project override is not built.
- Effective features: the personal `features`; else, in a solo project, the project's `user.comfort` answer; else hygiene + status line. A team or external-reviewer project ignores the project's answers (they are somebody else's choices).
- The one committed setting is Claude's `statusLine` in `.claude/settings.json`. It is written only for a solo project that picked it, with Claude selected. A team repository gets no status line; `yaw statusline --snippet` prints the JSON for `.claude/settings.local.json` (project) or `~/.claude/settings.json`. The kit writes no `settings.local.json` (answers ADR-0013's open question: no, nothing is written into git-ignored files either).
- The hook registrations are committed like every module's; they do nothing for a user who has not enabled the feature. State is under `~/.yaw/state/comfort/` (sessions, last check, hygiene switch), outside every repository; removing the module leaves it, like the registry of ADR-0029.

### Session hygiene (M14)

- On by default in Standard and Full, personal, switchable: not choosing it in `user.comfort`, or `yaw hygiene off [--all]` / `on [--all]` / `status`. "Uncheckable" in doc 11 is dropped (ADR-0013).
- `yaw hygiene off` is per project and stays off until `yaw hygiene on` (doc 11 said "for the session"): a CLI call does not know the session id, and a hint switched off for one session would return in the next one. `--all` covers every project.
- State per session in `~/.yaw/state/comfort/sessions/<agent>-<id>.json`: prompt count, start, topic vector (384 rounded numbers, the shared embedding of ADR-0011), the last two drifts, branch, task refs, the prompt number of the last hint, the turn start. Prompt text is embedded in memory and dropped; a state file with the wrong types is discarded.
- Per prompt: drift = 1 - cosine(prompt, topic vector), clamped to 0..1 and averaged over the last two prompts (evaluated from the third prompt on); topic vector = 0.8 old + 0.2 new; size = transcript bytes / prompts (from the fifth prompt; the payload's `transcript_path` is only `stat`-ed: absolute, normalised, `.jsonl`, inside the home, not a link); age since the first prompt; task switch = the prompt names a `T-NNN` the session did not start with, or the branch changed (reported once, then it becomes the session's own).
- Defaults: drift 0.9 (measured with the shared embedding: prompts on one topic 0.5 to 0.8, unrelated ones 0.95 and above), 60 prompts, 180 minutes, 100 KB per prompt, cooldown 20 prompts. The hint is one `systemMessage` naming the reasons and `/handoff` then `/clear` when the sessions module is installed (M8: a soft dependency, checked at run time in the manifest), otherwise `/clear`; it never blocks.

### Last `just check` (M8)

- Stored by the two evaluation hooks from the agent's own Bash calls: a command that is exactly `just check` (optional plain arguments, no shell operators, so the exit status is the recipe's) is a pass on PostToolUse and a fail on PostToolUseFailure. File `~/.yaw/state/comfort/check/<hash of the project path>.json` (status, time). Not in `yaw.db`: BD3 limits it to the registry tables.
- Limits, stated: only runs by the agent are seen (a run in the user's terminal is not), and only for Claude (Codex's PostToolUse cannot tell a failed run from a passed one; the status line is Claude-only anyway). Whether Claude reports a non-zero Bash exit as PostToolUseFailure is assumed from the hook docs and covered by a synthetic payload; a live recording is issue #94.
- Alternative rejected: have the `check` recipe write the status. It is defined per profile, so every profile and every user-edited justfile would need the change.

### Status line

- `yaw statusline` (the `statusLine` command) reads Claude's JSON from stdin and prints one line: active task (`TASKS.md`, read with the sessions module's link-refusing reader), context percentage, prompt-cache state, a hygiene badge once a hint was shown in the session, the last check and its age. It prints nothing on any error and exits 0; it is exempt from the token rule (rendered by the UI).
- The `context_window` and `prompt_cache` shapes are read defensively (several field names, unknown ones ignored, a missing segment is left out) because no live payload is recorded yet (#94).

### Notifications

- Triggers: Stop (done), Notification `permission_prompt` / `idle_prompt` (needs input), StopFailure (failed). Only when the turn took at least N minutes (default 3, `notify.minutes`), measured from the prompt's time; once per turn and kind.
- Payload: a closed set built from project folder name, task id, status, minutes and the active task's title. The agent's last message, tool input and output, prompts and diffs are never read. The title is cleaned (control characters, code spans, key-like tokens and anything unbroken over 24 characters become `[redacted]`) and cut to 80 characters.
- Channels in phase 1: terminal (OSC 9 default, OSC 777, or off; Claude returns it as `terminalSequence`, Codex gets a `systemMessage`) and ntfy (default server `https://ntfy.sh`, http only for localhost, no credentials in the URL, topic `[A-Za-z0-9_-]{1,64}`). ntfy goes out from a detached child (`lib/send.js`, no output, 8 s timeout, no redirects) so a hook never waits for the network; the child reads the topic from the personal file itself, so the topic is in no argument or log and `yaw notify status` shows only the host.
- `yaw notify status | test | send --status done|input|failed [--minutes N] [--summary text]`: `send` is for recipes and scripts.

### Path safety

Session ids match `[A-Za-z0-9][A-Za-z0-9._-]{0,127}`; state directories are created 0700 and refused when any component is a link, files are 0600 and written atomically, a linked state file is neither read nor written; `YAW_HOME` must be absolute; `comfort.yaml` must be a regular file of at most 64 KB and is schema-checked (invalid: defaults, reported by `yaw hygiene` and `yaw notify status`); the transcript path is only `stat`-ed (above).

### Not in this step

Cache-warmth reminder (phase 2, doc 11 §3), Telegram / Pushover / e-mail channels (the Telegram wrapper belongs to `remote`), a per-project notification override, notifying when a long `just check` or deploy ends, `yaw doctor` hints for the module, a `just hygiene` recipe, hygiene off for one session only.

## Consequences

- `templateContext` exposes `comfort` flags; `kickoff/11`, `kickoff/04`, `docs/spec/formats.md` and plan.md are updated; `config.schema.json` loses `hygiene`, `comfort.schema.json` and an example are new.
- The status line command and the hook shim each locate the kit; the status line runs often, one Node start each time.
