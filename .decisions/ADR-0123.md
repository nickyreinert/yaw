# ADR-0123: go-serverless profile: Go x serverless with hosting variants container and lambda (T-001)

- **Date:** 2026-10-30
- **Category:** Modules / Catalogue
- **Status:** Accepted
- **Importance:** normal
- **Scope:** `profiles/go-serverless/**`

## Context

T-001: Go x serverless. Pattern: ADR-0115 and ADR-0119 (ADR-0105 profile options, ADR-0116 tools).

## Decision

- go-serverless takes go x serverless. Option hosting (default container) selects variants/<choice>/; scaffold/ holds greeting.go.
- container: the go-web service (handler.go, Dockerfile). lambda: aws-lambda-go v1.47.0 pinned with a committed go.sum, Handler for API Gateway payload v2 (unescaped path, 405/404/400), tests call it directly; build writes dist/bootstrap for linux/arm64 (provided.al2023, lambda.norpc); no SAM template, deployment is yours.
- Tools (ADR-0116): aws for lambda. Dependabot ecosystem gomod (added to the profile schema). Guards: registry pushes, aws/sam/gcloud, go install, release tags, remote hosts.

## Consequences

Both flavors pass just check without Docker or an AWS account; lambda fetches aws-lambda-go once. The Dockerfile and the real Lambda deployment are never run by the kit and are unverified.
