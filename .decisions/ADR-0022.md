# ADR-0022: Minimal `security` module: guard rules and their limits

- **Date:** 2026-10-20
- **Category:** Security / Guards
- **Status:** Accepted
- **Importance:** high

## Context

BD6: phase-1 security denies reading `.env*` and secret files and guards `rm -rf`, force push and prod deploy; it is the blocking hook that proves step 4.

## Decision

- `guards.yaml`: `guards` (command regex), `secretFiles` (file-name regex), `secretAllow` (checked first); profiles may add rules.
- `guard-secret-read` and `guard-destructive` on `PreToolUse` deny with `YAW security (<id>): <reason>`; nothing on allow; the user runs a blocked command themselves.
- Static backstop: `permissions.deny` for the common secret files in `.claude/settings.json`.
- The guards are a seat belt, not a sandbox (obfuscated commands are not caught).

## Consequences

A false positive costs one round trip; rules are narrowed in `guards.yaml`.
