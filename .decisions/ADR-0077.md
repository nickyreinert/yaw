# ADR-0077: Three interview depths and one reusable setup wizard

- **Date:** 2026-10-28
- **Category:** Architecture / CLI
- **Status:** Superseded
- **Importance:** normal
- **Supersedes:** ADR-0032
- **Scope:** `core/interview/**`, `core/cli/init.js`, `core/web/**`
- **Superseded by:** ADR-0080

## Context

The user requested Quick essentials, Basic GitHub and review choices, Pro with every question, all optional tools off until chosen, and identical init and Settings interviews.

## Decision

Replace the offered Quick/Full choice with quick, basic and pro. Quick asks purpose and architecture including framework and hosting, library, service and cost constraints. Basic also asks repository agents, collaboration, GitHub and review gates. Pro asks every applicable implemented question regardless of expertise and exposes all modules. Reuse explicit saved personal and tool defaults; optional tools and review triggers are off if never chosen. Store tool defaults separately from personal preferences. Use one wizard shell and controller for initial browser setup and Settings, with drafts, planning, foundation review, preview and explicit Apply. Preserve existing project modules and confirmed proposals; retain legacy full/standard module selection when reading old files.

## Consequences

Fresh Quick output becomes core plus the selected profile. Depth no longer implies enabling optional modules or services. Existing explicit configurations remain supported and new defaults affect future setups only. Settings keeps the workspace open after Apply. No new hook output or model calls.
