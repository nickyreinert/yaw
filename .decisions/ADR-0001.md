# ADR-0001: YAML for human-edited files, JSON for kit-written files; strict YAML subset

- **Date:** 2026-10-20
- **Category:** Architecture / Formats
- **Status:** Accepted
- **Importance:** high

## Context

The kit has zero runtime dependencies, so no YAML library; full YAML has traps (anchors, tags, `no`/`on` typing). BD1 and BD2 fixed the outline.

## Decision

- YAML for files people edit (answers, module, profile, presets, `github.yaml`); JSON for kit-written files (manifest, ledger data, hook events, agent settings). Exception: `taxonomy.json` stays JSON.
- Parse a strict subset in `core/lib/yaml.js`: maps, lists, one-line scalars, flow collections, `|`/`>` block scalars, comments; YAML 1.2 core typing (`yes/no/on/off` and dates stay strings).
- Reject anchors, aliases, tags, multi-docs, multi-line plain scalars with `file:line: message`.
- The emitter writes a header saying comments are not preserved; the kit rewrites YAML only through explicit commands.

## Consequences

Surprising YAML cases cannot occur; some pasted YAML is rejected with a pointed error; hand-written comments are lost on explicit rewrites.
