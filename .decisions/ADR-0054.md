# ADR-0054: Stack = language x where it runs; tailored or basic profile per pair; suggestWhen removed

- **Date:** 2026-10-24
- **Category:** Modules / Catalogue
- **Status:** Superseded
- **Importance:** high
- **Scope:** `profiles/**`, `core/interview/**`, `core/web/**`, `core/cli/init.js`
- **Tags:** stack, profile, interview
- **Superseded by:** ADR-0085

## Context

The interview asked for a stack profile, a preferred language and a runtime separately. Users could not tell why all three existed, and the answers could contradict each other.

## Decision

The interview asks two questions: arch.language and arch.runs-on (local, server, serverless, edge, static, wordpress, desktop). Each profile declares stack.language and stack.runsOn; the pair selects the tailored profile, otherwise the language's basic profile (go, java, kotlin, node, php, python, rust, swift -basic). Pairs that cannot work (for example Rust inside WordPress) disable Continue / Preview with an explanation; a language is never disabled and local toolchains are not checked (yaw doctor reports missing tools). The profile question and the suggestWhen rules are removed; no migration because YAW is not released yet. Modules carry title, group, what, example and cost metadata so the browser form shows grouped cards with presets and a compact view.

## Consequences

One source of truth for the stack. The init terminal flow and the web form use the same confirmStack / profileForStack logic. Adding a stack means adding a profile with stack.language/runsOn. Earlier profile ADRs that mention suggestWhen describe the removed mechanism.
