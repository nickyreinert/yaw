# ADR-0102: node-web profile: TypeScript on node:http for your own server, split from node-basic (T-001)

- **Date:** 2026-10-30
- **Category:** Modules / Catalogue
- **Status:** Accepted
- **Importance:** normal
- **Scope:** `profiles/node-web/**`

## Context

T-001 replaces basic fallbacks per language and destination. JavaScript x self-hosted had only the zero-tooling node-basic profile.

## Decision

- Scaffold: strict TypeScript, pure Request to Response handler in src/app.ts, node:http adapter in src/server.ts (binds 127.0.0.1 by default), zero runtime dependencies, Vitest, ESLint, exact-pinned dev dependencies, multi-stage Dockerfile.
- Gate: lint, typecheck, test, an audit of shipped dependencies and a tsc build to dist/; no Docker, database or network beyond npm. The image build and the container are not part of the gate.
- Guards: image push, remote docker host or context, ssh/scp/sftp/rsync to a host, registry publishing.
- node-basic keeps static and app-store; suggestWhen stays empty (typescript plus self-hosted is not narrow enough).

## Consequences

A new project passes just check without Docker. The Dockerfile was not built here (Docker daemon down); the compiled server was started and answered requests directly.
