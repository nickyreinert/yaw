# ADR-0036: node-ts-vercel profile: plain TypeScript serverless scaffold, vercel.json, never auto-suggested

- **Date:** 2026-10-22
- **Category:** Modules / Catalogue
- **Status:** Proposed
- **Importance:** normal

## Context

Y-6.3 adds node-ts-vercel; doc 05 lists Next.js or Vite, Vercel CLI, `next build`, Playwright e2e, `npm audit`, and Vercel preview and prod.

## Decision

Scaffold: plain TypeScript (strict), one serverless function in api/ calling a function in src/, Vitest tests, ESLint (typescript-eslint), exact-pinned dev dependencies, vercel.json (docs name no vercel.ts; the config stays platform-only). Framework options (next, vite), `next build` and Playwright e2e wait for the full interview (step 7); those verbs print not applicable. Gate: lint, typecheck, test, npm audit --omit=dev; no Vercel account, deploy or network beyond npm. deploy runs only `npx vercel@65.0.0 deploy --prod`, and refuses in CI, without the argument prod and without YAW_CONFIRM_PROD=yes. Guards block every Vercel CLI form (bare vercel, npx, dlx, exec, bunx, name@version, env prefixes, chains), just deploy and YAW_CONFIRM_PROD, npm publish, ssh/scp/sftp; only --version and --help pass. suggestWhen is empty: no pair of facts is narrow enough (typescript plus serverless would also fit Cloudflare Workers, and an unknown fact would suggest it alone), so the user picks it from the list. The scaffold reads no project files, so no symlink handling is needed. CI: node-ts-vercel joins the profile matrix of kit-ci.yml; fixtures lint_error.ts and type_error.ts live in test/profiles/node-ts-vercel/.

## Consequences

A new project passes just check without Vercel; the profile is chosen manually until the full interview; deploy is tested only for its refusals.
