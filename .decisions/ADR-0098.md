# ADR-0098: Unit tests are an explicit project requirement

- **Date:** 2026-10-30
- **Category:** Modules / Workflow
- **Status:** Accepted
- **Importance:** normal
- **Scope:** `core/interview/**`, `core/lib/coding-practices.js`, `modules/review/**`

## Context

Settings previously had no unit-test opt-in, while Quality review prompts always mentioned missing tests. Docker was offered for incompatible deployment targets.

## Decision

Expose quality.unit-tests as an optional Coding Style switch, default false. Enabled projects require a meaningful non-empty unit-test suite in just check and the Quality reviewer treats missing, empty or failing suites as findings. Disabled projects do not require a unit-test suite. Docker applies only to local, self-hosted and serverless targets; omit inapplicable Docker answers from normalized settings and generated architecture instructions.

## Consequences

Quality remains an agent review governed by the existing warn/block push policy, rather than a language-independent test runner. Settings bootstrap uses local GitHub configuration checks to avoid blocking on network authentication.
