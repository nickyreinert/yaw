# ADR-0035: python-web profile: FastAPI scaffold, check without Docker or database, language-only suggestWhen

- **Date:** 2026-10-21
- **Category:** Modules / Catalogue
- **Status:** Proposed
- **Importance:** normal

## Context

Y-6.2 adds python-web; doc 05 lists Docker Compose, alembic on a temp DB, bandit, pip-audit, image build and Playwright, and suggests it for python on self-hosted or docker.

## Decision

Scaffold: FastAPI (uv, src/app, TestClient tests), no database; framework and db options wait for the full interview (step 7), so profile.yaml lists no options. Dockerfile and .dockerignore ship in the scaffold. Gate: lint (ruff + bandit), pyright, pytest, pip-audit; just check never needs Docker, a database or the network beyond uv and pip-audit. Alembic on a temp DB, Playwright screenshot and compose are not part of the profile yet (those verbs print not applicable). build runs docker build only, not part of check. Guards: docker push, ssh/scp, remote docker host, prod alembic, PyPI publish. suggestWhen is language [python] plus runsOn [self-hosted] (hasUI is left out, it carries no information): python plus app-store, edge or serverless is not suggested, python-cli wins for python plus local. Known limit: an unknown language (default auto) plus self-hosted suggests python-web alone, the user confirms the proposal. Guards also cover the bypass forms: build --push, buildx, compose push, DOCKER_HOST=ssh://, -H, alembic -x/-c with prod, sftp, rsync to a remote host. No lockfile is committed by the profile (uv.lock appears after just setup, as python-cli); the scaffold reads no project files, so no symlink handling is needed. CI: python-web joins the profile matrix of kit-ci.yml (setup-uv added, SHA-pinned); fixtures lint_error.py, insecure.py and type_error.py live in test/profiles/python-web/.

## Consequences

A new project passes just check without Docker; DB migrations, image build in CI and browser screenshots come with later ADRs; docker build is only tested by hand.
