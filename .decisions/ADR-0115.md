# ADR-0115: rust-serverless profile: Rust x serverless with hosting variants container and lambda (T-001)

- **Date:** 2026-10-30
- **Category:** Modules / Catalogue
- **Status:** Accepted
- **Importance:** normal
- **Scope:** `profiles/rust-serverless/**`

## Context

T-001: Rust x serverless only had rust-basic. Pattern: ADR-0107 (php-serverless) and ADR-0105 (profile options). Cited ADR-0054, ADR-0114.

## Decision

- rust-serverless takes rust x serverless; rust-basic keeps edge and app-store.
- Option hosting (default container) selects variants/<choice>/ (ADR-0105); scaffold/ holds src/greeting.rs with its unit tests, shared by both.
- container: the axum service of rust-web (router(), HOST/PORT, graceful shutdown, tower oneshot tests, multi-stage Dockerfile, .dockerignore). lambda: lambda_http handler(Request) -> Response, thin main with lambda_http::run, tests call handler() directly; no SAM template, deployment is cargo lambda by the user.
- Pins (cargo info and cargo search 2026-10-30), exact: axum 0.8.9, tokio 1.54.1, tower 0.5.3 (dev), lambda_http 1.3.2 (rust-version 1.84, so requires rustc>=1.84; it re-exports run, service_fn and Error, no separate lambda_runtime pin).
- Same gate for both: fmt --check, clippy -D warnings, cargo check, cargo test, audit (cargo-audit when installed), release build --locked. It needs no Docker, AWS account or cargo-lambda. dev runs the server (container) or cargo lambda watch when installed (lambda); build and deploy for the packaging steps only print notes.
- Guards: crates.io publish/owner/yank/login, cargo install and rustup changes, cargo lambda deploy/invoke/new/init, registry push (docker/podman/buildah/nerdctl, gcloud builds submit), cloud CLIs aws/sam/gcloud, release tags, remote hosts.
- CI: examples rust-serverless and rust-serverless-lambda join the kit-ci matrix; dependabot cargo.

## Consequences

Both flavors pass just check offline of any cloud. cargo lambda build (arm64 cross build) and the Dockerfile are never run by the kit, so those two steps are unverified. Blocking all aws/sam/gcloud commands also blocks read-only calls.
