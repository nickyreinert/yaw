# ADR-0113: rust-cli profile: Rust command-line tools on your computer, split from rust-basic (T-001)

- **Date:** 2026-10-30
- **Category:** Modules / Catalogue
- **Status:** Accepted
- **Importance:** normal
- **Scope:** `profiles/rust-cli/**`

## Context

T-001: Rust x local only had rust-basic. Cited ADR-0054, ADR-0104 (php-cli pattern), ADR-0110 (swift-cli).

## Decision

- rust-cli takes rust x local; rust-basic keeps self-hosted, serverless, edge and app-store until they are tailored.
- Scaffold: Cargo package app (edition 2021, rust-version 1.80, unsafe forbidden), lib with run(args, out, err) and injected writers, thin main.rs, unit tests plus a binary integration test via CARGO_BIN_EXE_app, no crates.
- Gate: cargo fmt --check, clippy -D warnings, cargo check --all-targets, cargo test; no Docker, no network (no crates). audit prints a note until crates exist (cargo-audit is a separate install).
- Guards: cargo publish/owner/yank/login, cargo install and rustup changes, release tag push, remote hosts.
- CI: actions-rust-lang/setup-rust-toolchain v1.17.0 pinned by SHA (git ls-remote); the SHA in rust-basic did not match any tag and is replaced by the same pin. The kit-ci profile job needs no Rust step because ubuntu-latest ships stable Rust with rustfmt and clippy (unverified until the first CI run).

## Consequences

A new Rust CLI project passes just check offline. Dependabot ecosystem cargo is added when a Rust profile with crates arrives.
