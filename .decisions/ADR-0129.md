# ADR-0129: browser-extension profile: HTML, CSS & JavaScript x browser extension (Manifest V3)

- **Date:** 2026-11-02
- **Category:** Modules / Catalogue
- **Status:** Accepted
- **Importance:** normal
- **Scope:** `profiles/browser-extension/**`

## Context

Chrome, Edge and Firefox extensions had no stack: they are plain HTML, CSS and JavaScript, but run inside the browser, not on a host. None of the existing destinations fits, so arch.runs-on gains `browser-extension`. Cited ADR-0054, ADR-0107, ADR-0128.

## Decision

- New destination `browser-extension` ("browser extension: Chrome, Edge, Firefox"); it is not a hosted runtime and Docker does not apply.
- browser-extension takes html x browser-extension. Scaffold: one Manifest V3 `extension/manifest.json` for all three browsers (Firefox keys under `browser_specific_settings`), a toolbar popup, no permissions, no build step.
- Gate: web-ext lint, html-validate, stylelint, scripts/check-manifest.mjs (Manifest V3, every named file inside extension/, no remote or inline scripts), npm audit. `just build` packs dist/<name>-<version>.zip with web-ext; `just dev [chromium]` loads it into a temporary browser profile.
- Store submission is not generated. Guards: web-ext sign, chrome-webstore-upload, npm publish.

## Consequences

A new extension passes just check offline of any store. TypeScript and other languages on browser-extension have no profile yet and are refused with the covered pairs.
