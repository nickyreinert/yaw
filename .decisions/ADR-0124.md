# ADR-0124: Keep form navigation separate from the technical file console

- **Date:** 2026-10-31
- **Category:** Architecture / CLI
- **Status:** Accepted
- **Importance:** normal
- **Supersedes:** ADR-0100
- **Scope:** `core/web/**`

## Context

The docked navigation displaced form actions, stretched file rows inherited interview grid styles, switchable groups appeared overemphasized, and a missing dashboard module left the startup status visible indefinitely.

## Decision

Keep Back and Continue at the bottom of the form. Dock only the compact monochrome project console above the full-width version footer, with a bounded scroll area, uniform 24px file and folder rows, and a fully clickable header. Filter to affected paths, expand their folders, and hide the console on Review and Apply. Retain the shared folder-and-purpose tree in the final review without previews, and authenticated on-demand planned/existing file previews restricted to allowlisted regular files, 128 KiB and no detected secrets. Keep switchable containers neutral and subdue inactive content. Explain communication choices briefly. Verify that the dashboard serves its complete browser module graph.

## Consequences

The console remains local presentation state and writes no project files. Startup cannot depend on an unserved module. Explicit step-start scrolling and the existing file-preview protections remain in force.
