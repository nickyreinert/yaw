# ADR-0028: decisions module: ADR + notice journal, task-start recall, user-visible recall note

- **Date:** 2026-10-21
- **Category:** Memory / Decisions
- **Status:** Proposed
- **Importance:** high
- **Scope:** `modules/decisions/**`

## Context

Doc 04 and the blueprint (D, E, F, K) describe a Markdown journal with a derived index and a recall hook that injects records on every prompt; BD9 / ADR-0007 forbid model-visible output on UserPromptSubmit, and BUILD.md rule 5 caps SessionStart output.

## Decision

- Keep records in `.decisions/` (Markdown is the truth); derive `decisions.index.json` from them with one `embeddingText` recipe; `just check` fails unless the index equals a rebuild and IDs are unique.
- IDs: `ADR-NNNN` / `NOTICE-NNNN` sequential, `ADR-<issue>-<n>` in team mode.
- Critical decisions at SessionStart: the user chooses how many are injected (one line each: ID and title); the default is 0 (none) and the maximum is 10; a larger value is rejected with "too many: the maximum is 10". Copilot does not support SessionStart context.
- One generated file, `.decisions/CRITICAL.md`, lists the critical decisions (ID and title) and is built from the index. AGENTS.md only references it (a reference line, never decision text). Claude and Codex get its lines through the SessionStart hook (up to the user's number); Copilot and other agents without SessionStart read the file. `decisions check` fails when the file drifts from the index.
- Storage (the `decisions` table in `yaw.db` is approved by the user as an extension of BD3): plain text in `.decisions/` is the source; `yaw.db` gets a `decisions` table as the discovery index. Embedded text per record: title + short summary + category path; the detail body is never embedded, only shown on retrieval.
- Categories: reuse `taxonomy.json` (Architecture, Agents, Modules, Memory, Security, Delivery, Governance) and add UI.
- Project name: `yaw init` asks one question (default: folder name), stored in the manifest; every decision row carries it; `yaw decisions` gets `--project`, `--model`, `--session`.
- Fallback and full records: the agent runs `just decisions recall "<task>"` at task start (critical records always included) and cites the IDs; the `UserPromptSubmit` hook is comfort: a `systemMessage` naming matching records to the user, never `additionalContext`.
- Gate recipes in `outputs.gates` run with `just check` through `sync-check`.
- Never follow symlinks or paths read from records; address records only as `.decisions/<ID>.md`.

## Consequences

Critical-decision lines per session are the user's choice (default none); the design update (storage, project name, CRITICAL.md) is not implemented yet; record bodies cost tokens only when the agent asks for them; a hand-edited record needs `just decisions rebuild`; YAW ADRs live in `.decisions/` from now on.
