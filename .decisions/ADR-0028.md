# ADR-0028: decisions module: ADR + notice journal, task-start recall, user-visible recall note

- **Date:** 2026-10-21
- **Category:** Memory / Decisions
- **Status:** Proposed
- **Importance:** high
- **Scope:** `modules/decisions/**`

## Context

Doc 04 and the blueprint (D, E, F, K) describe a Markdown journal with a derived index and a recall hook that injects records on every prompt; BD9 / ADR-0007 forbid model-visible output on UserPromptSubmit.

## Decision

- Keep records in `.decisions/` (Markdown is the truth); derive `decisions.index.json` from them with one `embeddingText` recipe; `just check` fails unless the index equals a rebuild and IDs are unique.
- IDs: `ADR-NNNN` / `NOTICE-NNNN` sequential, `ADR-<issue>-<n>` in team mode.
- The agent runs `just decisions recall "<task>"` at task start (critical records always included) and cites the IDs; the `UserPromptSubmit` hook is comfort: a `systemMessage` naming matching records to the user, never `additionalContext`.
- Gate recipes in `outputs.gates` run with `just check` through `sync-check`.
- Never follow symlinks or paths read from records; address records only as `.decisions/<ID>.md`.

## Consequences

Recall costs tokens only when the agent asks for it; a hand-edited record needs `just decisions rebuild`; YAW ADRs live in `.decisions/` from now on.
