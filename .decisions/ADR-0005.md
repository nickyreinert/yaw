# ADR-0005: JSON Schema subset and validator

- **Date:** 2026-10-20
- **Category:** Architecture / Formats
- **Status:** Accepted
- **Importance:** normal

## Context

Every format needs a machine-checkable definition with line numbers for YAML errors; a full JSON Schema implementation is too large for a zero-dependency kit.

## Decision

- Write schemas as JSON Schema 2020-12 in `core/schema/`, restricted to a documented keyword subset (structure, types, strings, numbers, arrays, objects, combinators).
- Reject any other keyword when a schema loads, so a typo cannot weaken a schema; resolve every `$ref` at load time.
- Report errors as `{ pointer, line, message }`, the line coming from the YAML parser.

## Consequences

Schemas stay readable by standard tools; cross-field rules live in code or tests.
