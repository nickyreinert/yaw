# ADR-0130: Concept import: another chat rewrites an existing concept; reviewed foundation updates replace current documents

- **Date:** 2026-11-02
- **Category:** Modules / Workflow
- **Status:** Accepted
- **Importance:** normal
- **Scope:** `core/lib/kickoff.js`, `core/lib/foundations.js`, `core/cli/kickoff.js`, `core/web/planning.js`, `core/web/assets/settings-view.js`

## Context

Users often arrive with a bigger concept from a browser chat. After yaw init, the kickoff prompts only knew the one-sentence idea and the setup choices; the local kickoff prompt writes foundation documents directly, and ADR-0075 refused to overwrite existing documents, so a concept could not be merged into them. YAW stays the single source of truth for setup facts and the plan format. Amends ADR-0075.

## Decision

- A concept prompt (yaw kickoff concept; Settings → Kickoff → Import your own concept) asks the chat that holds the concept to rewrite it in kickoff format 1. It carries the setup facts, which win over the concept (conflicts go to "Open questions" in the architecture foundation), and the complete current documents: registered foundations, else existing files at the default paths.
- Foundation action `update` (with the complete revised document) joins create and reuse. It requires an existing document, shows a diff (CLI --dry-run, browser preview) and is written only after explicit review and only when the file is unchanged since that review; create still refuses existing files.
- The reply is imported locally into the already-initialized project through the existing kickoff import and planning preview/apply; nothing is sent automatically.

## Consequences

A concept merges into documents a local agent already wrote, without a manual copy. Updated documents are replaced as a whole; content the chat drops is lost unless the reviewer catches it in the diff.
