# ADR-0045: Y-7.6: interactive secret entry writes only named values to a private local .env

- **Date:** 2026-10-23
- **Category:** Security / Guards
- **Status:** Superseded
- **Importance:** high
- **Scope:** `core/cli/**`, `core/web/**`, `core/render/**`
- **Superseded by:** ADR-0046

## Context

Doc 08 §3 reserves a hidden CLI prompt and a browser password field for entering secrets directly into the local project. Y-7.6 must keep entered values out of answers.yaml, presets, history, browser responses, logs and model-visible output. It does not define how names are selected or how an existing .env is handled.

## Decision

Offer only variable names listed in the generated .env.example; collect values after the user has confirmed Apply/setup, using a non-echoing terminal prompt or transient password inputs sent only to the authenticated loopback API. Treat blank values as skipped. Write only supplied values to .env using dotenv-compatible quoting and mode 0600. Never read or overwrite an existing .env; report that it was preserved without reading or returning any values. Never include secret values in answers, drafts, presets, history, summaries, errors, apply logs or API responses. Remote storage and keychain integration remain out of Y-7.6.

## Consequences

Secret entry is explicit and local. An existing .env is left untouched; users add or rotate values manually. Empty values are not persisted. Project-generated .env.example remains the names-only catalogue.
