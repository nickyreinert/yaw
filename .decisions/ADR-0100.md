# ADR-0100: python-vercel profile: Python serverless functions on Vercel, split from python-basic (T-001)

- **Date:** 2026-10-30
- **Category:** Modules / Catalogue
- **Status:** Accepted
- **Importance:** normal
- **Scope:** `profiles/python-vercel/**`

## Context

T-001 replaces basic fallbacks per language and destination. Serverless names Vercel, Netlify Functions and AWS Lambda, so a tailored profile needs one concrete target.

## Decision

- Target: Vercel for Python x serverless (same as node-ts-vercel); python-basic keeps edge and app-store.
- Scaffold: stdlib BaseHTTPRequestHandler in api/hello.py, logic in api/_greeting.py, zero runtime dependencies, vercel.json platform-only.
- Gate: ruff, pyright, pytest, bandit on api/, pip-audit; no Vercel account or production release at check time.
- Guards and the release recipe copy node-ts-vercel: every Vercel CLI form blocked, the recipe refuses in CI and without its production confirmation (ADR-0036).
- suggestWhen stays empty: python plus serverless is not narrow enough.

## Consequences

A new project passes just check without Vercel. The deployed function path and the import of _greeting inside the Vercel runtime are not verified locally; only the handler is tested over loopback.
