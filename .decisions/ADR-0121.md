# ADR-0121: go-cli profile: Go command-line tools on your computer, split from go-basic (T-001)

- **Date:** 2026-10-30
- **Category:** Modules / Catalogue
- **Status:** Accepted
- **Importance:** normal
- **Scope:** `profiles/go-cli/**`

## Context

T-001: Go x local only had go-basic. Pattern: ADR-0113 (rust-cli).

## Decision

- go-cli takes go x local; go-basic keeps app-store only (no sensible tailored Go app-store profile: gomobile needs Android SDK or Xcode and Wails a frontend toolchain, neither gateable offline).
- Scaffold: module example.com/app (go 1.22), run(args, stdout, stderr) int with injected streams, thin main, unit tests plus a built-binary exit-code test, standard library only.
- Gate: gofmt check, go vet, optional staticcheck, go build and go test -run '^$', go test; audit runs govulncheck when installed. Guards: go install, go run pkg@version, go env -w, release tags, remote hosts.
- CI: actions/setup-go v6.4.0 pinned by SHA (git ls-remote); the SHA go-basic carried matched no tag and is replaced. govulncheck v1.9.0 installed in CI.

## Consequences

A new Go CLI passes just check offline. Verified locally with Go 1.27.3 only; the minimum go 1.22 is not run with an older toolchain.
