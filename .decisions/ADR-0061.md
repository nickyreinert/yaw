# ADR-0061: Configurable session folders, Gemini CLI, sync of tasks and knowledge

- **Date:** 2026-10-25
- **Category:** Architecture / CLI
- **Status:** Accepted
- **Importance:** normal
- **Supersedes:** ADR-0060
- **Scope:** `core/lib/session-sources.js`, `core/lib/data-sync.js`, `modules/sessions/lib/import.js`

## Context

A scan only looked in each agent's fixed folder, so sessions kept elsewhere (other config dir, Flatpak, a second tool) never appeared, and nothing told the user. Users also asked to sync Global Tasks and global knowledge.

## Decision

Global settings → Sessions edits a list of {format, folder}; the scan, the web pages and 'yaw sessions import' read exactly the enabled folders (defaults when never saved), nothing is scanned implicitly. A Gemini CLI reader joins Claude Code, Codex and Copilot CLI; Cursor, Antigravity and VS Code chat are not readable. Sync gets two opt-in scopes: tasks (Global → Tasks snapshots as folder name plus items) and knowledge (~/.yaw/knowledge Markdown records, three-way merge with deletions). All ADR-0060 and ADR-0057 limits otherwise stay.

## Consequences

Task titles and knowledge text leave the machine in plain text, so both scopes are off by default and the page says so. Gemini folders named by a path hash are matched only to known projects. A path the user adds is read with the same no-follow checks as the defaults.
