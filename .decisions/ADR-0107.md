# ADR-0107: php-serverless profile: PHP x serverless with hosting variants container and bref; php-basic removed (T-001)

- **Date:** 2026-10-30
- **Category:** Modules / Catalogue
- **Status:** Accepted
- **Importance:** normal
- **Scope:** `profiles/php-serverless/**`

## Context

T-001: php-basic only covered php x serverless as a generic fallback. A basic profile needs at least one runsOn pair (schema minItems 1), so with its only pair tailored it has no reason to exist.

## Decision

- php-serverless takes php x serverless; php-basic is deleted (no pair left, runsOn cannot be empty); tests naming it are updated.
- Option hosting (default container, chosen by the user; label names the container or Bref choice) selects variants/<choice>/ (ADR-0105); scaffold/ holds Greeting, GreetingTest, PHPUnit and PHP-CS-Fixer config.
- container: public/index.php front controller calling App::handle, multi-stage Dockerfile (php:8.4-apache, listens on PORT, non-root), .dockerignore. bref: handler.php (Bref function) calling Handler::handle, template.yaml for AWS SAM with the Bref php-84 layer, PHPUnit test that parses the template as YAML (symfony/yaml), no SAM CLI.
- Same gate for both: php-cs-fixer dry run, phpstan level 8, phpunit, composer audit --locked; needs no Docker, AWS account or SAM CLI. dev runs php -S for container; deploy and build only print a note.
- Pins (packagist metadata 2026-10-30): bref/bref 3.0.14, symfony/yaml 7.4.22, phpunit 11.5.57, phpstan 2.1.56, php-cs-fixer 3.95.27 (as php-cli, ADR-0104).
- Guards: composer global/self-update, registry push (docker/podman push, gcloud builds submit), cloud CLIs aws/sam/gcloud, remote hosts (ssh, scp, rsync to host, DOCKER_HOST, docker context).
- CI: examples php-serverless and php-serverless-bref join the kit-ci matrix; dependabot covers composer.

## Consequences

A php x serverless project gets a runnable scaffold and a gate that needs no cloud account. The Bref layer version in template.yaml is a placeholder parameter (default 1) the user must set; the Dockerfile and SAM template are never built or deployed by the kit. Blocking all aws/sam/gcloud commands also blocks read-only calls.
