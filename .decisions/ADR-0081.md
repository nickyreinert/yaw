# ADR-0081: Keep Interview as a Settings feature instead of a URL path

- **Date:** 2026-10-28
- **Category:** Architecture / CLI
- **Status:** Superseded
- **Importance:** normal
- **Scope:** `core/web/assets/**`
- **Tags:** routes
- **Superseded by:** ADR-0088

## Context

The interview is reused within Settings and should not appear as a page path in either workspace or global settings.

## Decision

Use #settings and #global-settings for their default panels. Accept ?interview as an optional feature flag and preserve section and search query parameters. Canonicalize legacy /interview links to the Settings root while keeping other Settings tabs and file deep links working. Search results may select an interview section through ?interview&section=... using the shared wizard.

## Consequences

Existing bookmarks still open, visible URLs no longer present Interview as a separate Settings page, and section navigation keeps entered answers until Apply.
