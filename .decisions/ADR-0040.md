# ADR-0040: android-kotlin profile: Compose scaffold, gate needs the Android SDK but no emulator or keystore, signing and publishing are user-only, never auto-suggested

- **Date:** 2026-10-22
- **Category:** Modules / Catalogue
- **Status:** Proposed
- **Importance:** normal

## Context

Y-6.7 adds android-kotlin; doc 05 lists Gradle, the Android SDK and an emulator as dev env, `ktlint`/`detekt`, Android Lint, unit tests and `assembleRelease` as the gate, Paparazzi or emulator + `adb screencap` / Maestro as screenshot, Play Console tracks (Fastlane) as deploy target, and "upload to production track, keystore access" as guards. The plan row asks for an SDK cache and a documented runner. Doc 05 §1 adds the device verbs `device-pair`, `device-install`, `device-screenshot`, `device-log` for the remote dev loop (doc 11 §4, phase 3).

## Decision

Scaffold: one Compose app module (`app`, package `com.example.app`; `greeting()` in plain Kotlin, a thin `MainActivity` with one `@Composable`), a JUnit 4 unit test on the JVM, version catalog `gradle/libs.versions.toml`, `.editorconfig` and `config/detekt/detekt.yml` (both only exempt `@Composable` functions from the function-naming rules), minSdk 26, compileSdk and targetSdk 36, build tools 36.0.0. The Gradle wrapper (script, `.bat`, jar, properties with `distributionSha256Sum`) is part of the scaffold, generated by `./gradlew wrapper` of Gradle 9.8.2 itself; `just setup` makes `gradlew` executable because the render engine does not keep file modes.

Exact versions, all looked up on 2026-10-22 (and the combination built and run once, see Consequences): Gradle 9.8.2 (`services.gradle.org/versions/current`, built 2026-10-19; checksum from `gradle-9.8.2-bin.zip.sha256`), Android Gradle Plugin 9.4.1 (Google Maven; 9.5.0-rc01 is a release candidate and not used), Kotlin 2.4.21 (Maven Central; the Compose compiler plugin has the same version; AGP 9 has built-in Kotlin, so no `kotlin-android` plugin), ktlint Gradle plugin 14.2.0 (Gradle plugin portal) with ktlint 1.8.0 (Maven Central, set explicitly), detekt 1.23.8 (latest stable; `dev.detekt` 2.0.0-alpha.6 is an alpha and not used), JUnit 4.13.2 (latest; AGP runs JUnit 4 without a third-party plugin, JUnit 5 would need one), Compose BOM 2026.06.01 with activity-compose 1.13.0 (BOM 2026.09.00 and newer libraries need compileSdk 37; 2026.06.01 builds against the installed SDK 36). CI: Temurin JDK 21 (local run: JBR 21.0.11); AGP 9 needs JDK 17 or newer, which `just setup` checks.

Gate (`just check`): `ktlintCheck detekt lintDebug`, `compileDebugKotlin compileDebugUnitTestKotlin`, `testDebugUnitTest`, `sync-check`. It needs the Android SDK (`ANDROID_HOME` or `local.properties`): Android Lint and the compile read the platform jars. It needs no emulator, device, keystore, signing key or store account. Network: only the Gradle distribution (checked by the pinned checksum) and Gradle plugin / Maven / Google Maven dependencies. Therefore the CI job needs the SDK and caches it (below).

Deviations from doc 05, row updated in the same commit:
- `assembleRelease` is not in `check`: a release build is signed with the user's keystore (or fails unsigned), and R8 costs minutes. `build` runs `assembleDebug`; the user runs release builds.
- No emulator in the gate or in CI (no KVM on the runner). `dev` installs the debug build on a running emulator or device (`installDebug`); the user starts the emulator.
- No Paparazzi, `adb screencap` or Maestro screenshot yet (as ADR-0036 to ADR-0039): `screenshot` prints not applicable. The device verbs of doc 11 §4 (`device-*`) are phase 3 and not part of the fixed verb set; they are not built.
- No dependency audit: doc 05 lists none for Android, so `audit` prints not applicable.
- Deploy: no Fastlane recipe yet. `deploy` prints a note and exits 0, and refuses (exit 1) when `CI` is set, so nothing is published or signed from CI or by the recipe.

Guards (tested against bypass forms: path prefixes, env prefixes, sudo, nohup, time, xargs, command, `sh gradlew`, bash -c / sh -c, chains, subshells, command substitution, newlines): `gradle-publish` blocks any `publish*` or `promote*` Gradle task (also `:app:publishReleaseBundle`, quoted) for `./gradlew`, `gradlew`, `gradlew.bat`, `gradle`; `gradle-release` blocks `bundle` and `bundle*Release`, `install*Release`, `sign*` tasks, `android.injected.signing` and keystore-style `-P` properties; `signing-tools` blocks every `apksigner` and `jarsigner` form and `keytool` with any option except `-help`, `-printcert`, `-version` (so `-genkey`, `-genkeypair`, `-importkeystore`, `-list` on a keystore are blocked); `fastlane` blocks every Fastlane form except `--version`, `--help`, `lanes`, `actions`, `action`, `env` (also behind `bundle exec`, `bundler exec`, `rbenv exec`, `gem exec`), every `bundle exec fastlane` form and the bare `supply` and `deliver` binaries at a command position; `cloud-cli` blocks `gcloud` and `bq` with any argument except `--version`, `--help`, `-h`, `help`, `version`; `adb-release-install` blocks `adb install`, `install-multiple` and `install-multi-package` with `release` in any argument. Allowed and tested: `./gradlew test`, `lint`, `assembleDebug`, `assembleRelease` (unsigned, no signing material), `installDebug`, `bundleDebug`, `tasks`, `adb install` of debug builds, `adb logcat|devices|shell|pull|uninstall`. `secretFiles`: `*.jks`, `*.keystore`, `keystore.properties`, so the security module denies reading them. No `ssh` guard and no `just deploy` guard: doc 05 names none and `deploy` is inert.

suggestWhen is empty: the interview has no Android or Kotlin fact (language choices are python, javascript, typescript, auto), so no fact is narrow enough and the user picks the profile from the list.

Symlinks: the recipes read no project files. `_wrapper`, which every Gradle recipe (and `setup`) runs first, refuses a missing or symlinked `gradlew`, `gradle`, `gradle/wrapper`, `gradle-wrapper.jar` and `gradle-wrapper.properties` (`[ -L ]` per path), so a linked wrapper never runs; tested with a marker script. Gradle itself reads the project; its own symlink behaviour is not changed here.

CI: android-kotlin joins the profile matrix of kit-ci.yml, conditional steps (SHA-pinned, `contents: read` only, no secrets): `actions/setup-java` (Temurin 21), a step that sets `ANDROID_HOME` / `ANDROID_SDK_ROOT` to `~/android-sdk`, `actions/cache` for `~/android-sdk`, `~/.gradle/caches` and `~/.gradle/wrapper` (key from the scaffold files), `android-actions/setup-android` (cmdline tools, licenses, `platform-tools platforms;android-36 build-tools;36.0.0`). Runner: `ubuntu-latest`, no emulator, no KVM; macOS would work the same way but is not needed (documented in doc 05). The fragment `profiles/android-kotlin/ci/check.yml` does the same for the quality-gate workflow of a project. The SDK is pinned in CI and in `app/build.gradle.kts` (`compileSdk`, `buildToolsVersion`) to the same platform and build tools. Fixtures `lint_error.kt` (wildcard import, spacing) and `type_error.kt` live in test/profiles/android-kotlin/.

## Consequences

A new project passes just check with JDK 17+ and the Android SDK, without an emulator, a keystore or a store account; the profile is chosen manually until the interview knows Android. The smoke test ran here (macOS, JBR 21.0.11, SDK platform 36, Gradle cache warm: `yaw init` + `just check` and both failing fixtures) and is skipped where java, `ANDROID_HOME` or the network is missing. The GitHub Actions steps (setup-android, the cache keys, the SDK location override) could not be run locally; the first CI run is their test. `deploy`, `dev` (installDebug) and `build` outside the gate were not run against a device. The scaffold carries a binary file (`gradle-wrapper.jar`, 48749 bytes, sha256 3b8a2577...a68e98) generated by Gradle 9.8.2; `yaw update` treats it as user code like the rest of the scaffold. Detekt 1.23.8 is built for Kotlin 2.0.21 and analysed the Kotlin 2.4.21 scaffold without error; newer language features may need detekt 2.x once it is stable.

## Known gaps (later issue, not built)

- Gradle task name abbreviations (`./gradlew bunR`, `pTML` for camel-case matches), tasks read from a script or `GRADLE_ARGS`, and a quoted or indirect command name (`"./gradlew" publish`, `g=./gradlew; $g publish`).
- A `signingConfig` in the project that reads a keystore from the environment makes a plain `assembleRelease` signed; the guard does not look at the project files (standards.md forbids a signingConfig with a path or password).
- `bundletool build-apks --ks`, `zipalign`, `adb push` + `pm install` of a release APK, `adb install` of a release build under a name without `release`.
- Fastlane through `rake`, `make`, `npx`, or a Fastfile lane called from another script; Google Cloud through `gsutil`, `firebase`, `curl` to a Google API; Play publishing through the Play Developer API with `curl`.
- `keytool` allows `-printcert` on any file; `apksigner` / `jarsigner` / `keytool` are blocked as words even in `echo` or `which`.
- Paparazzi / Maestro screenshots, the `device-*` verbs, emulator tests in CI, a Fastlane `deploy` recipe and a dependency audit.
