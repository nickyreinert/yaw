# ADR-0083: Treat setup and kickoff as one resumable planning workflow

- **Date:** 2026-10-28
- **Category:** Architecture / CLI
- **Status:** Superseded
- **Importance:** normal
- **Scope:** `core/web/**`, `core/lib/kickoff.js`
- **Tags:** planning
- **Superseded by:** ADR-0096

## Context

Early setup and post-init prompts already requested the same foundations and tasks but appeared as separate rounds.

## Decision

Use one planning card and delivery interface. Carry a complete reviewed early reply through Apply and show plan ready; continue partial or context-changed plans with existing work and authoritative sources. Track relevant project setup facts by hash, excluding personal preferences. Offer browser copy-and-paste or an explicitly confirmed installed-agent text draft through a separate restricted runner, independent of Learn defaults. Later workspace imports require source preview, acknowledgement and concurrency checks, without replacing authoritative documents.

## Consequences

A second LLM round is optional. The standalone init server still closes after Apply; live follow-up uses the workspace, with manual copy handoff available on completion. No new hook output, autonomous provisioning or automatic acceptance of model drafts.
