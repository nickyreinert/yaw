# ADR-0076: Collect separate architecture control dependency and cost constraints and review UI layout examples before implementation

- **Date:** 2026-10-28
- **Category:** Architecture / CLI
- **Status:** Superseded
- **Importance:** normal
- **Scope:** `interview/base.yaml`, `core/lib/kickoff.js`, `core/lib/foundations.js`, `core/cli/kickoff.js`, `kickoff/**`
- **Tags:** kickoff, constraints, mockups
- **Superseded by:** ADR-0080

## Context

The user requested mockups covering layout as well as colours and noted that hosting control, third-party reuse and paid subscriptions influence kickoff architecture. These dimensions were absent from implemented setup questions and CONCEPT.md focused only on Global Improve.

## Decision

Extend ADR-0075 with project-scoped Quick and Full choices for hosting control, library policy, external application services and cost policy, plus a conditional budget cap with currency and period. Keep undecided values explicit; they do not block deterministic kit installation or grant purchase or provisioning consent. Carry exact saved choices into kickoff and structured agent context independently of language/runtime profile selection and personal preferences. Ask about missing limits or contradictions before architectural commitment; document build/reuse trade-offs, data boundaries, ongoing costs and exit options in architecture. Generic practices and kickoff revision 2 offer proportionate wireframes, mockups or clickable examples before substantial UI implementation. Review layout, hierarchy, navigation, control placement and key states before colours and typography; link accepted examples and observable criteria from the UI/UX foundation. Reuse existing approved designs and scale examples to the change. Bundle and index format 1 remain compatible; no new hook output or automatic model call.

## Consequences

On-premises deployments can use third-party open-source libraries; managed hosting does not itself authorize external application services. Free software can still incur hosting and maintenance costs, and free tiers may expire or charge overage. Unknown constraints require a later project decision. Visual approval does not prove usability or accessibility. Existing answers without these fields remain valid and their prompts ask for the missing constraints. Preserve the existing Global Improve concept and add a linked kickoff workstream with explicit remaining validation limits.
