# ADR-0069: Private remote hub and agent-independent managed execution

- **Date:** 2026-10-28
- **Category:** Security / Guards
- **Status:** Superseded
- **Importance:** normal
- **Scope:** `core/remote/**`, `core/cli/remote.js`, `core/lib/data-sync.js`, `adapters/remote-claude/**`, `docs/remote-control.md`
- **Superseded by:** ADR-0071

## Context

CONCEPT-REMOTE-CONTROL.md is now authorized for implementation. Existing hooks and analytics cannot supervise agent processes or own shared revisions.

## Decision

Add yaw remote serve as a separate loopback service accessed through an SSH tunnel. One owner credential and revocable browser sessions control registered NAS checkouts; paired devices receive data-only credentials. Browser and Telegram use one supervisor and explicit managed/provider IDs. Claude SDK and Codex app-server are optional execution adapters behind the same capability interface. Linux bubblewrap isolates worker filesystems and process namespaces; controller credentials are excluded. Store only lifecycle metadata, command receipts and credential hashes separately from analytics. Content buffers are temporary and bounded; restart invalidates decisions and marks delivery unknown. Hub revisions use compare-and-swap with explicit conflicts and a writer migration boundary for folder sync.

## Consequences

No live-process adoption, silent prompt replay, public reverse proxy, multi-user hosting or automatic deployment. Claude is an optional pinned dependency, not a core dependency. Host quotas and actual NAS/provider compatibility require deployment validation. ADR-0007, ADR-0018, ADR-0029 and ADR-0061 remain in force.
