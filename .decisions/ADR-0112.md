# ADR-0112: swift-app profile: SwiftUI app as a Swift package for Swift x app-store; swift-basic removed (T-001)

- **Date:** 2026-10-30
- **Category:** Modules / Catalogue
- **Status:** Accepted
- **Importance:** normal
- **Scope:** `profiles/swift-app/**`

## Context

T-001: Swift x app-store only had swift-basic. The task allowed keeping the pair on swift-basic if the gate needed Xcode. It does not: SwiftPM builds a SwiftUI executable with swift build on macOS without an Xcode project or signing. A basic profile needs one runsOn pair (ADR-0107), so with all three Swift pairs tailored swift-basic is deleted. Cited ADR-0054, ADR-0107, ADR-0110.

## Decision

- swift-app takes swift x app-store; swift-basic is deleted and tests naming it are updated.
- Scaffold: package for macOS 14 with the UI-free AppCore library (Counter), the app executable with SwiftUI views inside canImport(SwiftUI) (an #else branch prints a note, so the package builds on Linux), XCTest tests of the logic.
- Gate: swift format lint --strict, swift build --build-tests, swift test; no Xcode project, signing, Apple account or network. The SwiftUI views are compiled by the gate only on macOS; the generated project CI runs on ubuntu and therefore tests AppCore only.
- Not covered: the shippable app. An Xcode app target (bundle id, icons, entitlements), signing, notarization and App Store Connect upload are the user's, stated in the profile note, standards and the deploy verb. The kit never creates an .xcodeproj (gitignored).
- Guards: release tag push, xcrun altool/notarytool/stapler, xcodebuild -exportArchive and -allowProvisioningUpdates, fastlane, keychain and signing changes (security import/unlock-keychain/add-trusted-cert, codesign --sign), registry publishing, remote hosts.
- CI: kit-ci runs the swift-app example on macos-latest with the runner's Swift (the matrix runs-on switches per profile).

## Consequences

Swift app projects get a gate that exercises UI code on macOS only; UI compile errors surface in the local just check on a Mac and in kit CI, not in the ubuntu project CI. macOS runner Swift and swift format availability is unverified until the first kit CI run.
