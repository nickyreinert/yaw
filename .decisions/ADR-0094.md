# ADR-0094: LAN server roles provision managed projects and launch native Claude Remote Control

- **Date:** 2026-10-29
- **Category:** Architecture / CLI
- **Status:** Accepted
- **Importance:** normal
- **Supersedes:** ADR-0071, ADR-0063
- **Scope:** `core/remote/**`, `core/cli/host*`, `core/lib/remote-settings.js`, `core/web/assets/global-settings-view.js`

## Context

The user replaced SDK-based remote coding supervision with optional Host and Client roles, shared data, managed workspace initialization and server-only Telegram setup.

## Decision

Keep machine-local opt-in, default off. Host enablement requires explicit confirmation of <current-folder>/workspaces and persists that absolute root. init remains current-directory setup; init-local and init-remote use the host workspace at <language>/<required-slug>, share validated interviews and select exactly one native Claude agent. Clients pair with host approval and automatically sync portable settings, presets and statistics. A persistent host launches native Claude Remote Control; coding prompts and tool approvals remain in Claude. Telegram interviews, process supervision and lifecycle notifications belong only to the Host service. Preserve token-free hook output and existing sync authority migration rules.

## Consequences

Current transport is trusted LAN HTTP only: concrete private interfaces, pinned private DNS, peer/Host/Origin checks, no redirects or forwarded proxies, scoped revocable device credentials, local owner control, CSRF, bounded inputs and atomic project creation. Native processes run under the dedicated host account; first-run native trust remains explicit. Public hosting requires a separate TLS, identity, proxy, isolation and audit design before enabling it. Old SDK service remains a compatibility path for pre-role configurations. Agent response completion is distinct from task completion and verification.
