# ADR-0125: java-cli profile: Java command-line tools on your computer, split from java-basic (T-001)

- **Date:** 2026-10-31
- **Category:** Modules / Catalogue
- **Status:** Accepted
- **Importance:** normal
- **Scope:** `profiles/java-cli/**`

## Context

T-001: Java x local only had java-basic. Pattern: ADR-0117 (kotlin-cli).

## Decision

- java-cli takes java x local; java-basic keeps app-store only (no sensible tailored Java app-store profile: it would be an Android app and the Android SDK is not gateable offline; to consider later).
- Scaffold: Gradle wrapper (checksum-pinned, same as kotlin-cli), application plugin, Java 17 via options.release, App.run(args, out, err) with injected Appendables, thin Main, JUnit 5 tests, no libraries.
- Gate: Spotless with google-java-format 1.28.0 (lint = spotlessCheck, fmt = spotlessApply), javac -Xlint:all -Werror (typecheck), tests, build. No audit recipe is implemented (Dependabot watches Gradle). Guards: gradle publish, release tags, remote hosts.
- CI: JDK 17 (temurin) for java- profiles; examples/java-cli joins the kit-ci matrix.

## Consequences

A new Java CLI passes just check with network access to Maven Central and the Gradle distribution. Verified locally with JDK 21 only; JDK 17 as minimum is checked in CI only.
