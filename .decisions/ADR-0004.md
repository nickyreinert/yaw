# ADR-0004: Shared-file composition and fragment ownership; just `import` vs. `mod`; `core` removability

- **Date:** 2026-10-20
- **Category:** Architecture / Rendering
- **Status:** Accepted
- **Importance:** high

## Context

Several modules write into AGENTS.md, the justfile, .gitignore, the PR template and the agent settings; removal must delete exactly a module's part. Rejected: patching regions in place (second merge mechanism), no shared files.

## Decision

- `core` owns every shared file and renders it whole from all modules' parts: text parts in `<!-- yaw:<m> -->` / `# yaw:<m>` blocks, JSON parts merged (lists concatenate, conflicting scalars are an error). Fragments are hashed in the manifest.
- Every change re-renders the whole file and goes through the ADR-0003 update flow; unregistering hooks is the same mechanism.
- A module with recipes ships `just/<name>.just` and one `import` line; module recipes never reuse the uniform verbs; several profiles use `mod`.
- `core` is removable, as the last module.

## Consequences

One mechanism for every change; an edited shared file gets one keep / take / merge question when modules change.
