# ADR-0119: kotlin-serverless profile: Kotlin x serverless with hosting variants container and lambda (T-001)

- **Date:** 2026-10-30
- **Category:** Modules / Catalogue
- **Status:** Accepted
- **Importance:** normal
- **Scope:** `profiles/kotlin-serverless/**`

## Context

T-001: Kotlin x serverless. Pattern: ADR-0115 (rust-serverless), ADR-0107 and ADR-0105 (profile options). Cited ADR-0116 (tools list).

## Decision

- kotlin-serverless takes kotlin x serverless. Option hosting (default container) selects variants/<choice>/ (ADR-0105); scaffold/ holds the wrapper, settings and Greeting.kt.
- container: the Ktor service of kotlin-web (module(), HOST/PORT, testApplication tests, Dockerfile, .dockerignore). lambda: class Handler implementing RequestHandler<APIGatewayV2HTTPEvent, APIGatewayV2HTTPResponse> (handler com.example.app.Handler::handleRequest), tests call it directly; same routes and status codes. No SAM template: deployment is the user's.
- Pins, exact: Ktor BOM 3.6.1, logback 1.6.6 (container); aws-lambda-java-core 1.4.1, aws-lambda-java-events 3.16.1 (lambda). Lambda package: a buildZip task (classes at top level, runtime libraries in lib/), run by build, written to build/distributions/app-0.0.0.zip.
- Tools (ADR-0116) for lambda: aws and sam, shown at profile pick and listed at the end of init when missing.
- Same gate as kotlin-cli for both. dev: gradlew run (container) or a note (lambda, no local server). Guards: gradle publish, registry pushes, aws/sam/gcloud, release tags, remote hosts. CI: examples kotlin-serverless and kotlin-serverless-lambda join the kit-ci matrix.

## Consequences

Both flavors pass just check offline of any cloud; verified locally with JDK 21 (ktlint, tests, build, zip contents). The Dockerfile and the Lambda deployment (runtime java17, handler string, API Gateway payload format 2.0) are never run by the kit, so they are unverified. Blocking all aws/sam/gcloud commands also blocks read-only calls.
