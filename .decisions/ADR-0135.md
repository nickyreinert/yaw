# ADR-0135: Session classification v2: per-exchange, separate assistant and user subjects, 1-5 scales, frustration tags, calibration

- **Date:** 2026-11-10
- **Category:** Memory / Sessions
- **Status:** Proposed
- **Importance:** normal
- **Scope:** `core/lib/session-analysis.js`, `core/web/**`
- **Tags:** classification, learn

## Context

Current Laya classification sends one mixed state per turn, has criteria only for outcome, applies an uncalibrated 0.65 threshold, saves only counts, treats Claude meta and command lines as user prompts, and hides categories and criteria from the user. Sentiment is shown as user reaction but never scoped to the user.

## Decision

Classify per exchange (human prompt, assistant reply, next human prompt) with two Laya calls: assistant reply without the reaction, user reaction with prompt and a named answer excerpt. Fixed category set with editable instructions, descriptions and thresholds; no user-defined categories. Scales are 1-5, derived from 5-level choice probabilities, not Laya score. Frustration markers are yes/no tags. Deterministic transcript signals take precedence. Save per-exchange labels with index and fingerprint, no text; sync only session roll-ups. Calibrate with user labels and a JS temperature fit. Keep Laya, loopback-only, explicit runs and ADR-0068 phrase rules. Spec: kickoff/17-session-classification.md. Accepting and implementing it supersedes ADR-0068.

## Consequences

Two calls per exchange roughly double run time. Turn indices are now stored locally, which changes the CONCEPT.md privacy statement. Schema 1 results stay as legacy until reclassified. Results remain conversation estimates; uncalibrated categories are marked. Laya HTTP details must be verified before implementation.
