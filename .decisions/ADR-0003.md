# ADR-0003: Hash and merge strategy for `yaw update`

- **Date:** 2026-10-20
- **Category:** Architecture / Rendering
- **Status:** Accepted
- **Importance:** high

## Context

`yaw update` must never overwrite a user's edits and needs a base for three-way merges; the manifest has hashes but no content. Rejected: re-rendering the old tag, hidden git objects, no base.

## Decision

- Hash `sha256:` over the content with CRLF normalised; a file is edited when its hash differs from the manifest.
- Keep the pristine render of every managed file in `.yaw/base/<path>` (committed).
- Unedited + changed: overwrite silently. Edited + changed: keep / take / merge (`git merge-file`); conflicts stay marked and are reported. Non-interactive: keep.
- `managed: false` files are never written by update; missing files are reported (`--restore`, `--forget`), not recreated.

## Consequences

One base copy per managed file; user edits are never lost without an explicit take.
