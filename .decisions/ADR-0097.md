# ADR-0097: Keep setup lean and carry explicit engineering preferences with five gated reviewers

- **Date:** 2026-10-29
- **Category:** Architecture / Rendering
- **Status:** Accepted
- **Importance:** normal
- **Supersedes:** ADR-0090, ADR-0055
- **Scope:** `core/interview/**`, `core/web/**`, `core/lib/coding-practices.js`, `modules/core/**`, `modules/review/**`

## Context

The user requested a split personal step, a lean Architecture step with Docker and library strategy, configurable error/log/documentation rules, restored card details and a Security reviewer. Existing architecture questions and a four-reviewer catalogue no longer match that flow.

## Decision

Step 2 groups agents and experience separately from Communication style and moves its optional module card there. Step 4 offers language/runtime, prefer-built-in versus suitable libraries, and a Docker requirement switch. Retire framework, hosting ownership, services and cost questions from new interviews; retain validated explicit legacy values and direct legacy edits, including their runtime applicability. Basic/All expose new project practices while Quick reuses defaults. Step 5 restores a persisted Compact switch and uses normal-width cards for all five reviewers and the push gate. Extend quality/logic/UX/feature reviews with Security using the same off/request/suggest/push triggers, read-only agent adapters, layered prompts, per-commit cache and warn/block pre-push semantics; warn still blocks unattended pushes. Security references applicable OWASP ASVS 5.0.0 and logging/error-handling guidance, without claiming compliance. Keep personal preferences out of shared team rules. Core generates docs/engineering.md with behavior/regression/failure/security testing, explicit errors, safe structured logs and maintained documentation, linked from AGENTS.md within its existing line budget; optional standards link that same source. Error detail, console/file/both logs and essential/detailed documentation are project choices. Carry Docker/library choices and those rules into synchronized kickoff and planning context; Docker is a requirement for later local-agent work, not provisioning. Prefer cohesive units and stack tools over blanket line counts or 100 percent coverage claims. Preserve the authenticated REST setup, full chat dropdown, copy-only prompt flow, explicit Apply and ADR-0007 limits.

## Consequences

Generated engineering rules remain available when optional standards are off. File logs require bounded storage, rotation, redaction, retention and access controls. Existing authoritative specifications and legacy constraints remain reviewable. LLM review and passing test recipes are evidence, not guarantees. The supplied Copilot document is treated as reference material; its disabled authentication, unconditional Python/async restrictions, silent failure example and arbitrary code-size caps are not copied as defaults.
