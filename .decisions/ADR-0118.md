# ADR-0118: kotlin-web profile: Kotlin x self-hosted, Ktor service with Dockerfile (T-001)

- **Date:** 2026-10-30
- **Category:** Modules / Catalogue
- **Status:** Accepted
- **Importance:** normal
- **Scope:** `profiles/kotlin-web/**`

## Context

T-001: Kotlin x self-hosted. Pattern: ADR-0114 (rust-web), ADR-0117 (kotlin-cli).

## Decision

- kotlin-web takes kotlin x self-hosted.
- Ktor 3.6.1 (BOM) on Netty, logback-classic 1.6.6, all exact; test host via ktor-server-test-host. Routes in Application.module() (GET /, GET /health, GET /hello/{name} with a 100 char limit), main reads HOST (127.0.0.1) and PORT (8080) and starts Netty with wait=true, which stops gracefully on SIGTERM.
- Tests drive module() with testApplication: no sockets, network or database.
- Dockerfile: multi-stage, eclipse-temurin 17 JDK builds installDist with the wrapper, 17 JRE runs as a non-root user with HOST=0.0.0.0 PORT=8080; .dockerignore.
- Gate as kotlin-cli (ktlintCheck, compile, test, build installDist); dev is gradlew run. Guards: gradle publish, image pushes, remote hosts and Docker contexts, release tags. CI as kotlin-cli; dependabot gradle.

## Consequences

Verified locally: ktlintCheck, tests, build and a started server answering /health and /hello/Ada. The Dockerfile is never built by the kit or by me (no Docker daemon check made), so the image build is unverified. Dependabot docker ecosystem is not configured, so the base image tags are not watched.
