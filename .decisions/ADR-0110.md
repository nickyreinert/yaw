# ADR-0110: swift-cli profile: Swift command-line tools on your computer, split from swift-basic (T-001)

- **Date:** 2026-10-30
- **Category:** Modules / Catalogue
- **Status:** Accepted
- **Importance:** normal
- **Scope:** `profiles/swift-cli/**`

## Context

T-001 replaces basic fallbacks per language and destination. Swift x local only had swift-basic. Decision retrieval cited ADR-0054 (one profile per pair), ADR-0104 (php-cli pattern).

## Decision

- swift-cli takes swift x local; swift-basic keeps self-hosted and app-store until they are tailored.
- Scaffold: SwiftPM tools 5.9, library AppCore (runCli with an injected TextSink for stdout/stderr), thin executable target app, XCTest tests, no third-party package.
- Gate: swift format lint --strict (the Swift 6 toolchain ships swift format, so requires swift>=6.0), swift build --build-tests, swift test; no Xcode, signing, Docker or network. audit prints a note (SwiftPM has no audit command, no dependencies).
- Guards: release tag push, swift package-registry publish, pod trunk push, remote hosts (ssh, scp, sftp, ftp, rsync to a host).
- CI: swift-actions/setup-swift v2.4.0 pinned by SHA (verified with git ls-remote); example swift-cli joins the kit-ci matrix. The SHA in the old swift-basic fragment did not match any tag and is not reused.
- suggestWhen stays empty.

## Consequences

A new Swift CLI project passes just check on macOS and Linux. The smoke test also runs the tool with and without arguments.
