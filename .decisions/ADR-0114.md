# ADR-0114: rust-web profile: Rust x self-hosted as an axum service with a Dockerfile (T-001)

- **Date:** 2026-10-30
- **Category:** Modules / Catalogue
- **Status:** Accepted
- **Importance:** normal
- **Scope:** `profiles/rust-web/**`

## Context

T-001: Rust x self-hosted only had rust-basic. Cited ADR-0054, ADR-0102 (node-web pattern), ADR-0113.

## Decision

- rust-web takes rust x self-hosted; rust-basic keeps serverless, edge and app-store.
- Crates (crates.io, verified with cargo search 2026-10-30), direct dependencies pinned with =: axum 0.8.9 (http1, tokio only), tokio 1.54.1, dev tower 0.5.3 (util). Cargo.lock is created by cargo fetch in setup and committed by the user.
- Scaffold: lib router() (GET /health, /, /hello/{name}), thin main reading HOST and PORT with graceful shutdown, tests through tower oneshot (no sockets), multi-stage Dockerfile (rust:1.96-slim-bookworm, cargo build --locked, debian:bookworm-slim, non-root; tags verified on Docker Hub), .dockerignore.
- Gate: fmt --check, clippy -D warnings, cargo check, cargo test, audit, release build; no Docker, no database. audit runs cargo audit when installed and otherwise prints a note; project CI installs cargo-audit with taiki-e/install-action v2.88.0 pinned by SHA.
- Guards: crates.io publish/owner/yank/login, cargo install and rustup changes, release tags, docker/podman push, remote hosts (ssh, scp, sftp, DOCKER_HOST, docker -H/--context).
- CI: example rust-web joins the kit-ci matrix (ubuntu-latest ships Rust with rustfmt and clippy; unverified until the first run); dependabot ecosystem cargo.

## Consequences

Locally the audit step is skipped without cargo-audit; the CI gate fails on known advisories. The Dockerfile is never built by the kit.
