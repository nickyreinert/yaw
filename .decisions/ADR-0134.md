# ADR-0134: Personal or team per setting: personal answers live only in ~/.yaw/user-profile.yaml (T-027)

- **Date:** 2026-11-08
- **Category:** Architecture / Formats
- **Status:** Accepted
- **Importance:** high
- **Scope:** `core/render/project.js`, `core/interview/policy.js`, `core/lib/user-store.js`, `core/render/kit.js`, `modules/compact/lib/levers.js`, `core/web/assets/interview-view.js`

## Context

Communication Style, chat language, autonomy, agents and comfort choices were written to .yaw/answers.yaml and, in solo projects, rendered into AGENTS.md, the Claude output style and .claude/settings.json. In a team they synced through Git and overwrote each other. ADR-0013 kept them out of team repositories only; compact had its own personal scope in ~/.yaw/compact.json.

## Decision

- Every interview setting is personal or team. The question's scope field sets the default: scope user (all user.* questions, user.agents included) is personal, the others team. scope team (hooks such as compact.levers, idea.*, arch.*, the profile options and the coding-rule quality questions) cannot be switched.
- A project switches a setting with the scopes map of .yaw/answers.yaml (question id: personal | team). The setup form shows a Personal switch on each switchable setting and warns before a team setting becomes personal that teammates will stop seeing it.
- Personal values are written only to ~/.yaw/user-profile.yaml (merged, never committed); team values only to .yaw/answers.yaml. Readers merge the profile over the project answers. An older answers.yaml that still holds personal answers is read as the fallback and cleaned on the next yaw update (the saved profile wins).
- A personal setting never reaches a committed file, solo or team: AGENTS.md gets the chat-language, autonomy and style lines, the Claude output style and the status line only when the project switched those settings to team. The agent files follow the agents of the manifest.
- compact.levers is a team setting: compact.personal, ~/.yaw/compact.json and the personal precedence are removed; YAW_COMPACT=0|1 still overrides per shell.
- "Who works on this project?" is Solo or Team; a saved external-reviewers reads as team.
- Library calls without env (no user folder) write answers as given; the CLI and the web setup always pass it.

## Consequences

Personal answers are saved to ~/.yaw/user-profile.yaml on every init, add, edit and update, also without the profile opt-in of ADR-0043, and that file is global: the last saved personal answers are the person's settings for all projects. Solo projects lose the committed style, chat language and status line unless switched to team. Replaces the solo rendering rule of ADR-0013 and the personal compact scope of T-049. Amends ADR-0079: Quick and Basic/Pro save the personal answers of a setup, a later project's personal answers change them for every project (no project-specific override unless the setting is switched to team), and core instructions no longer carry the personal style in solo projects; an invalid or unreadable profile is still never overwritten (ADR-0043), the setup only warns. A hosted interview (yaw remote) saves its personal answers to the host's profile.
