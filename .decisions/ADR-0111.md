# ADR-0111: swift-web profile: Swift x self-hosted as a Hummingbird service with a Dockerfile (T-001)

- **Date:** 2026-10-30
- **Category:** Modules / Catalogue
- **Status:** Accepted
- **Importance:** normal
- **Scope:** `profiles/swift-web/**`

## Context

T-001: Swift x self-hosted only had swift-basic. Cited ADR-0054, ADR-0102 (node-web pattern), ADR-0110. Vapor pulls a much larger dependency set; plain NIO still needs swift-nio and gives no router or in-process test client.

## Decision

- swift-web takes swift x self-hosted. Server: Hummingbird, exact 2.26.0 (the newest tag whose Package.swift needs tools 6.1; 2.27+ needs Swift 6.2). Requires swift>=6.1.
- Scaffold: AppCore library with buildRouter() (GET /health, /, /hello/:name) and buildApplication, thin app executable reading HOST and PORT, XCTest tests via HummingbirdTesting .router (no sockets), multi-stage Dockerfile (static Swift stdlib, non-root), .dockerignore.
- Gate: swift format lint --strict, swift build --build-tests, swift test, release build; no Docker, no database. audit prints a note (SwiftPM has no audit command); Dependabot ecosystem swift watches the pins, so the profile schema enum gains swift and cargo.
- Guards: release tag push, docker/podman push, remote hosts (ssh, scp, sftp, DOCKER_HOST, docker -H/--context), swift package-registry and pod trunk push.
- CI: example swift-web joins the kit-ci matrix with the same pinned setup-swift step as swift-cli. swift-basic keeps app-store only.

## Consequences

The first gate run compiles Hummingbird and swift-nio (about 2 minutes). The Dockerfile is never built by the kit. Hummingbird upgrades are Dependabot PRs and may raise the required Swift version.
