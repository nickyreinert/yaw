# ADR-0034: static-site profile: lint tools, audit scope, narrow suggestion

- **Date:** 2026-10-21
- **Category:** Modules / Catalogue
- **Status:** Proposed
- **Importance:** normal

## Context

Y-6.1 adds the static-site profile; doc 05 lists html-validate, stylelint, link check and a Lighthouse budget, and the suggestion facts have no language for plain HTML.

## Decision

- Gate: html-validate 10.0.0 and stylelint (pinned) for lint; a zero-dependency Node script checks local links and anchors as test; Lighthouse budget and Playwright screenshot are not part of the profile (heavy, need a browser), those verbs print not applicable.
- html-validate is pinned to 10.0.0: newer 10.x and 11.x need Node 22.16+ or fail npm 10 installs (Cannot read properties of null, edgesOut), and the kit floor is Node 22.13.
- audit runs npm audit --omit=dev: the site ships static files, and the linters currently carry a high advisory (braces via stylelint) that would turn every new project red.
- suggestWhen: empty, so the profile is never auto-suggested and the user picks it from the list. runsOn would also match python-web and similar later profiles; public (from idea.audience) is not narrow either.
- Link check refuses targets outside public/ (realpath) and symlinked pages; queries are stripped and targets percent-decoded.
- Known limits (as node-cli): no committed lockfile, and npm audit does not cover dev tools (linters).
- CI: one job per profile in kit-ci.yml (matrix), running yaw init with examples/<profile>/answers.yaml; broken-page fixtures live in test/profiles/static-site/.

## Consequences

A new site passes just check without Lighthouse; dev-tool advisories are not caught by the gate; bump the html-validate pin when the kit floor moves.
