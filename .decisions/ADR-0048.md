# ADR-0048: Terminal confirmation is a workflow guard, not proof of human identity

- **Date:** 2026-10-23
- **Category:** Security / Guards
- **Status:** Accepted
- **Importance:** high

## Context

ADR-0027 already notes that Codex and other agents may acquire a pseudo-terminal. Such an agent can satisfy the terminal checks and type y itself. Raw GitHub CLI calls also exist outside YAW's guarded recipes.

## Decision

Retain explicit confirmation, the absence of a yes flag and the instruction that only the user runs guarded actions. Do not describe the TTY check as a non-bypassable human-identity or authorization boundary. Claude permission prompts conservatively cover all raw gh api calls, including short-method flags and GraphQL mutations, plus issue creation and Project item additions. These prefix prompts are defense in depth, not a sandbox. Enforce real authorization through credential scope, repository permissions and branch rulesets; agents must never synthesize user consent.

## Consequences

Codex with PTY access needs its own approval/tool restrictions or a user-run terminal for guarded work. Copilot likewise relies on host approvals and repository permissions. Prompt wrappers cannot prevent arbitrary tools from using available credentials. Verification is local with injected CLI responses, not a live agent or GitHub certification. A POSIX PTY regression uses an existing Python 3 interpreter solely as a test bridge: a program types y through a real terminal and the synthetic mutation succeeds, demonstrating the limitation without contacting GitHub. The test also verifies that the confirmation reader closes so guarded commands exit normally. It is explicitly skipped when POSIX/Python 3 is unavailable; neither is a new runtime dependency.
