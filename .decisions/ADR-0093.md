# ADR-0093: Use All depth and defer CLI tool selection to Workflow

- **Date:** 2026-10-29
- **Category:** Architecture / CLI
- **Status:** Accepted
- **Importance:** normal
- **Scope:** `core/cli/init*`, `core/interview/**`
- **Tags:** interview, ui

## Context

The terminal init selected modules before project questions and mixed browser shortcuts, help and long details with input prompts.

## Decision

Display Quick, Basic and All across terminal and browser; retain existing internal depth values. Order CLI questions as personal preferences, project, stack and workflow, while preserving the shared answer catalogue order on disk. In All, select optional modules after the stack and GitHub choice, using grouped numbered choices, concise purpose lines and explicit dependency notes. Follow up only on selected modules and retain other saved or factory defaults. Keep help, skip and browser switching immediately above every supported input, including retries; indent details and help consistently. Carry confirmed module choices and dependencies in browser handoffs. Keep explicit file review and Apply, personal-default boundaries and ADR-0007 hook behavior.

## Consequences

Terminal and browser retain output parity. Number lists accept mixed names and numbers with validation before selection. GitHub-dependent tools are unavailable when GitHub is off. Legacy invalid presets are not migrated by this change.
