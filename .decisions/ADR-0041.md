# ADR-0041: Profile composition: each profile is a just mod in its own folder, the root justfile defines the uniform verbs and calls every profile

- **Date:** 2026-10-22
- **Category:** Architecture / Rendering
- **Status:** Proposed
- **Importance:** normal

## Context

Y-6.8 (#68) combines profiles (static-site + cloudflare-workers). ADR-0004 already decides mod over import for several profiles and that core's frame defines the uniform verbs, but not where the profiles' files live (both ship package.json at the root), how a module recipe reaches the root-only sync-check, or what dev and deploy mean with two profiles.

## Decision

- With 2 or more profiles, each profile is rendered as mod <profile> 'just/<profile>.just' (namespace = profile name, just <profile>::<verb> stays available); with one profile nothing changes (flat import).
- Scaffold and recipes of a profile live in <profile>/ (scaffold files are written to <profile>/..., the module file starts with set working-directory := '../<profile>'). Root files (justfile, .gitignore, AGENTS.md, .claude) stay shared and composed by core.
- The root justfile frame (modules/core/templates/justfile.tmpl, text from composedVerbs() in core/render/kit.js) defines every uniform verb as a dependency list over the profiles in order; check is <profile>::check ... sync-check so a failing gate in any profile fails the top level. sync-check runs once at the root: the module copy of a profile's check drops its sync-check dependency (the render fails if a profile's check line does not end with sync-check).
- dev and preview start servers that never end, so at the top level they only print the namespaced commands. deploy env passes the argument to every profile's deploy, so each profile keeps its own refusals.
- Guards, standards and CI steps already join over all profiles of the manifest; secret-file guards match the file name, so they still hold inside <profile>/.
- Removing a profile (answers proposal.profiles and manifest profiles edited, then yaw update) removes exactly its just file, its mod line and its gitignore block; its folder is user code and stays.

## Consequences

Two profiles work without new modules or manifest fields. Limits: no command yet changes the profile list (ADR-0004: answers change plus yaw apply), so the test edits answers.yaml and the manifest by hand; a project that drops to one profile gets the flat layout again, but the remaining code stays in its <profile>/ folder and the user moves it; the first profile's folder is not at the root, so tools that look for package.json at the root need the namespaced verbs; profiles with a check line that does not end with sync-check cannot be composed until their file is fixed.
