# ADR-0117: kotlin-cli profile: Kotlin x local, JVM command-line tool on Gradle; kotlin-basic removed (T-001)

- **Date:** 2026-10-30
- **Category:** Modules / Catalogue
- **Status:** Accepted
- **Importance:** normal
- **Scope:** `profiles/kotlin-cli/**`

## Context

T-001: Kotlin x local, self-hosted and serverless only had kotlin-basic, which offered no run or packaging path. Cited ADR-0054, ADR-0113. This ADR also removes kotlin-basic: its three pairs are now all owned by tailored profiles; Kotlin app-store stays android-kotlin.

## Decision

- kotlin-cli takes kotlin x local; kotlin-basic is deleted (like php-basic, swift-basic) because no pair remains uncovered.
- Gradle application plugin, mainClass com.example.app.MainKt; logic in run(args, out, err): Int and greeting(); Main.kt only calls exitProcess(run(...)). Exit 0 on success, 2 on bad arguments (usage on stderr).
- Pins, exact: Kotlin plugin 2.2.20, ktlint plugin 13.1.0, JUnit BOM 5.12.2, Gradle wrapper 9.8.2 (checksum-pinned). No third-party library.
- No jvmToolchain: it requires an exact JDK 17 and fails on machines with only JDK 21 (kotlin-basic did this). Instead java source/target 17 plus Kotlin jvmTarget 17, so any JDK 17+ builds Java 17 bytecode.
- Gate: ktlintCheck, compileKotlin, compileTestKotlin, test, build installDist; dev is gradlew run with args. audit, deploy and the rest print a not-applicable note.
- Guards: gradle publish, release tags, remote hosts. CI: JDK 17 (temurin), just setup, just check; dependabot gradle.

## Consequences

Verified on this machine with JDK 21 and Gradle 9.8.2: ktlintCheck, test, build and the installed launcher. JDK 17 itself is not installed here, so the CI run on JDK 17 is the first check of that exact version. Publishing is blocked by pattern only (gradle publish).
