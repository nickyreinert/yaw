# ADR-0019: Phase-1 CLI surface and the behaviour of the step-2 commands

- **Date:** 2026-10-20
- **Category:** Architecture / CLI
- **Status:** Accepted
- **Importance:** normal

## Context

The docs name many `yaw` commands but no list (S2), the minimal step-2 `init` was open (S3), and ADR-0003 left flag names open.

## Decision

- Fixed phase-1 command list; a planned command exits 1. Amended: describe it as "not implemented", with an honest alternative or limitation, instead of promising a completed phase's step.
- `parseArgs` in strict mode; exit 0 on success, 1 on every error, refusal or conflict; prompts only on a terminal.
- `update [--yes] [--strategy keep|take|merge] [--restore p] [--forget p]`; `remove <module>` shows its plan and keeps edited files without an explicit flag.
- `doctor` and `status` report kit, manifest, files and tools.
- `web` (added with #172, ADR-0050) opens the read-only dashboard, or the setup form when the folder has no YAW setup.
- `kickoff [import <plan.md> [--dry-run]]` (added with #173) prints the planning prompt and imports the plan through `task new`.
- Bare `yaw`, `yaw --help` and `yaw help` group implemented commands into project setup and maintenance, planning and project work, monitoring and collaboration, YAW internal commands, and agent integration helpers. Each implemented command appears exactly once. `apply`, `config` and `session` remain separately labelled placeholders: their command handlers do not exist. `apply` has the supported `update` re-rendering alternative; no `.yaw/config.yaml` settings implementation or native agent-session renaming exists.

## Consequences

Later steps fill in rows of the existing command list; a new phase-1 command needs an update here.
