# ADR-0031: team module: ruleset + pr-policy + lefthook as the boundary, agent rules as guidance, session-start sync

- **Date:** 2026-10-21
- **Category:** Modules / Workflow
- **Status:** Proposed
- **Importance:** high

## Context

Doc 14 §2-§3 asks for team-mode enforcement in layers; BD3 limits pr-policy to the open-issue rule; BUILD.md rule 5 allows the model only the active task at session start; guarded GitHub writes need a person at a terminal (ADR-0027).

## Decision

- A team module (Standard and Full for a team; depends on tasks, github, git-hooks) owns the enforcement; removing it removes every layer.
- Security boundary (decided by the user): the GitHub ruleset (PR required, no force push, no deletion, no bypass) plus pr-policy plus lefthook. There is no agent-side command guard; the AGENTS.md rules (issue branch, no push to the default branch, no force, no --no-verify) are guidance only.
- lefthook commit-msg needs #<n>; pre-push is a script so lefthook cannot skip it; pr-policy.yml checks closingIssuesReferences for an open issue of this repository, read-only, no action.
- gh protect applies stay guarded; --verify only reads. SessionStart: fetch, fast-forward only when clean and not ahead (no git hooks run), divergence reported as information, gh reads cached 5 min in ~/.yaw/cache, offline fail-open; the user gets a systemMessage, the model one active-issue line.

## Consequences

An agent can break the local rules (commit on main, --no-verify); the ruleset and pr-policy stop it at GitHub, so the ruleset must be applied (just gh-protect) for the boundary to exist. closingIssuesReferences is empty for PRs into other branches. No just sync, Project fields or phase rules yet.
