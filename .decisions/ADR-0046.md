# ADR-0046: Y-7.6: skip automatic project verification after saving new secrets

- **Date:** 2026-10-23
- **Category:** Security / Guards
- **Status:** Accepted
- **Importance:** high
- **Supersedes:** ADR-0045
- **Scope:** `core/cli/**`, `core/web/**`

## Context

The Y-8.1 review found that YAW saved newly entered credentials to .env before automatically running just setup and just check. A retained project-owned justfile can read .env and exfiltrate these newly entered values. Verification must not run untrusted project recipes with newly entered credentials available.

## Decision

Supersede ADR-0045's verification sequencing while retaining its secret-entry protections: ask for secrets only after explicit setup confirmation; write only the supplied values for names in .env.example to a new .env (mode 0600); never read or overwrite an existing .env; never place values in answers, drafts, presets, history, logs, summaries, errors or responses. If YAW writes at least one new secret value, skip automatic just setup and just check and tell the user to review the project recipes before running them manually. If no value is saved, keep existing automatic verification behavior. Apply the same rule to CLI and browser flows.

## Consequences

Projects that receive new secrets need manual review and verification, so YAW does not run project-controlled commands while those new values are available. The project is applied successfully but verification is reported as skipped. An existing .env is outside this new-secret protection and remains user-managed.
