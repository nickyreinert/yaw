# ADR-0088: Open workspace Settings as a grouped form with optional Interview mode

- **Date:** 2026-10-28
- **Category:** Architecture / Rendering
- **Status:** Accepted
- **Importance:** normal
- **Supersedes:** ADR-0081
- **Scope:** `core/web/assets/**`
- **Tags:** settings, interview

## Context

Configured workspaces currently enter the setup wizard at Settings even when users only want to edit their settings.

## Decision

The workspace Settings root shows all applicable project settings in grouped form using the shared interview controls and controller. Interview is an explicit presentation switch using #settings?interview; changing presentation preserves edited answers, module selections and saved depth, and neither saves nor applies changes. Keep preview, Apply confirmation and optimistic concurrency. Init still opens the step-by-step wizard. Retain #global-settings for personal defaults, preserve search/section query parameters and other Settings tabs, and canonicalize legacy /interview links to the Interview feature flag.

## Consequences

Settings supports direct editing while the reusable wizard stays available after initialization. Returning to the Settings root selects the form; no persisted Interview preference overrides this default.
