# ADR-0075: Separate project ground truth from generic kit practices in guided kickoff and agent context

- **Date:** 2026-10-28
- **Category:** Architecture / CLI
- **Status:** Accepted
- **Importance:** normal
- **Supersedes:** ADR-0073
- **Scope:** `core/lib/foundations.js`, `core/lib/kickoff.js`, `core/cli/kickoff.js`, `core/web/init.js`, `modules/review/**`
- **Tags:** foundations, kickoff, agent-context

## Context

Work packages 3 and 4 require reviewed architecture/domain, data and UX foundations. The user clarified that project ground truth and reusable agent practices are separate scopes.

## Decision

Guided kickoff format 1 drafts or reuses three project-owned Markdown sources before deriving tasks with spec links and observable acceptance. Require explicit review, preflight all sources and refuse overwrites or stale browser reviews. The .yaw/foundations.json index records paths, review hashes, kit and practices versions; generated artifacts are user-owned manifest entries. yaw kickoff context (text or JSON), optional yaw kickoff ux and read-only reviewers separate generic kit practices from current project sources. Project rules and applicable decisions constrain practices; surface conflicts for a project decision. Preserve legacy phase plans, deterministic setup and reviewer prompt precedence. No new per-prompt hook output, automatic external model call or mandatory embedding service.

## Consequences

Markdown stays canonical; changed sources appear with review warnings. Agents still retrieve relevant ADRs and linked knowledge and read complete excerpted documents. Model drafts are not user evidence. Reviewer PASS caching remains per commit under ADR-0056; request a fresh review when context outside that commit changes. CLI, static-site, data-backed-app and existing-repository integration fixtures exercise import, preservation and traceability; product validation remains project work.
