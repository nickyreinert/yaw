# ADR-0011: Shared retrieval engine in `core/lib/` and a Unicode-aware tokenizer

- **Date:** 2026-10-21
- **Category:** Memory / Decisions
- **Status:** Proposed
- **Importance:** normal
- **Scope:** `core/lib/retrieval.js`

## Context

The blueprint keeps the retrieval code inside the decision journal (M1), though sessions, knowledge and evaluation need it too, and tokenizes with `[a-z0-9]+`, which splits German words at every umlaut (M2).

## Decision

- Keep tokenizer, embedding, cosine, taxonomy classification, scope globs and the ranking pipeline in `core/lib/retrieval.js` (pure, no I/O); store code stays in its module.
- Normalise with NFKC + lower case; tokens are runs of `\p{L}\p{N}` of two or more code points; English and German function words are dropped before embedding (not before classification); no stemming or transliteration.
- Embed with the blueprint's 384-dim feature hashing, trigrams over code points; model tag `local-hash-ngram-v2`; vectors rounded to 4 decimals.
- Keywords hit exactly, by prefix (≥ 4 code points) or suffix (≥ 5). Pipeline: best pair (+ a tie) for decisions, all pairs for notices, threshold 0.12 × importance weight, retired records never, critical and scope matches always, the best decision of a best pair even below the threshold.

## Consequences

One engine for every memory store; German prompts classify and rank; a tokenizer change is a model bump that `just check` reports until `yaw decisions rebuild`.
