# ADR-0079: Personal defaults belong to installation and Basic or Pro interviews

- **Date:** 2026-10-28
- **Category:** Architecture / CLI
- **Status:** Accepted
- **Importance:** normal
- **Supersedes:** ADR-0074
- **Scope:** `core/cli/**`, `core/interview/**`, `core/lib/user-store.js`, `core/web/**`, `install.sh`, `modules/core/templates/AGENTS.md.tmpl`

## Context

The user found the init menu crowded and requested installer onboarding, an unobtrusive missing-defaults notice, factory defaults in Quick and editable personal defaults in Basic/Pro. Existing project overrides must not change saved global preferences.

## Decision

Replace the init u menu with a first-question offer on fresh interactive installation and a standalone yaw defaults command. Keep unattended installations and update reruns noninteractive, including piped installers with a controlling terminal. Quick reuses saved or factory preferences without asking or implicitly saving them. Basic and Pro ask experience, chat language, autonomy, answer length, tone, examples and explanation style using saved/factory values. A notice outside the menu explains that first confirmed Basic/Pro personal answers seed defaults after Apply when none exist. Exclude project agents, architecture, GitHub and optional tools from automatic seeding. Existing defaults are never automatically replaced; use explicit global editing to change them. Cancelled setups, previews, drafts, existing-project edits and noninteractive answers never seed them. Preserve legacy profile fields and invalid profiles. Core instructions apply personal style in solo projects even with optional communication output styles disabled; preserve team personal-rule suppression. Preset saving remains an independent opt-in.

## Consequences

Amend the Basic question policy in ADR-0077 and onboarding/profile-saving portions of ADR-0043 while preserving its secret refusal, private file permissions and preset guarantees. Supersede the optional init-menu onboarding contract in ADR-0074. Only confirmed personal questions are seeded, not unvisited browser defaults or tool preferences. No project files or presets are written by installer onboarding, no new dependencies or hook output.
