# ADR-0126: java-web profile: Java HTTP service for your own server or container host (T-001)

- **Date:** 2026-10-31
- **Category:** Modules / Catalogue
- **Status:** Accepted
- **Importance:** normal
- **Scope:** `profiles/java-web/**`

## Context

T-001: Java x self-hosted. Pattern: ADR-0118 (kotlin-web), ADR-0125 (java-cli).

## Decision

- java-web takes java x self-hosted.
- No framework: the JDK's built-in com.sun.net.httpserver, so the scaffold has no runtime libraries to pin or patch (a framework such as Spring Boot or Javalin is a choice for the project). Routes are a pure function Routes.handle(method, path) (GET /, GET /health, GET /hello/{name} with a 100 char limit, 405 for other methods); Server.main reads HOST (127.0.0.1) and PORT (8080) and stops gracefully on SIGTERM via a shutdown hook.
- Tests call Routes.handle directly: no sockets, network or database.
- Dockerfile: multi-stage, eclipse-temurin 17 JDK builds installDist with the wrapper, 17 JRE runs as a non-root user with HOST=0.0.0.0 PORT=8080; .dockerignore.
- Gate as java-cli (spotlessCheck, compile with -Xlint:all -Werror, test, build installDist); dev is gradlew run. Guards: gradle publish, image pushes, remote hosts and Docker contexts, release tags. CI as java-cli.

## Consequences

Verified locally: spotlessCheck, tests, build, a started server answering /health and /hello/Ada. The Dockerfile is never built by the kit or by me, so the image build is unverified; base image tags are not watched by Dependabot. JDK 17 minimum is checked in CI only.
