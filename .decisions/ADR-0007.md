# ADR-0007: Hook output policy (token-free hooks)

- **Date:** 2026-10-20
- **Category:** Agents / Hooks
- **Status:** Accepted
- **Importance:** critical

## Context

Hook output that reaches the model costs tokens every time it fires; BD9 / BUILD.md rule 5 split hooks into evaluation, comfort, context and guard. Async hooks are no loophole.

## Decision

- `evaluation`: print nothing, exit 0. `comfort`: synchronous `systemMessage` / `terminalSequence` only, never `additionalContext`. `context`: `additionalContext` on `SessionStart` only, at most 10 lines / 1000 characters. `guard`: `permissionDecision: deny` with a one-line reason, nothing on allow.
- The dispatcher drops whatever a handler's kind does not allow and mutes handler prints; exit code is always 0; output is one JSON object or nothing; no `async` hooks.
- Prompt-time recall (decisions) uses the comfort form; the agent reads records itself at task start. The only other model-visible output: `SessionStart` re-injection of the critical decisions the user chose (default 0, maximum 10), ID and title only (BUILD.md rule 5, ADR-0028).
- Amendment (2026-11-08, T-052, kickoff/16-compact-output.md §5): kind `compress`, `PostToolUse` only, returns only `updatedToolOutput` in the tool's own shape (Claude Code; Copilot `modifiedResult` unverified, Codex none). The dispatcher drops any result that is not smaller than the original; the result may end with one recall line. `tokenCost: none`. Tool output goes to compress handlers only, in memory, never to a log; the event record gets only `rawBytes`, `outBytes` and `method`.

## Consequences

A module's token cost is visible in its hook kinds; a new output type needs an amendment here.
