# ADR-0131: Concept handoff: another chat adapts a concept for the local coding agent; one prompt choice at the end of init

- **Date:** 2026-11-02
- **Category:** Modules / Workflow
- **Status:** Accepted
- **Importance:** normal
- **Scope:** `core/lib/setup-prompts.js`, `core/lib/kickoff.js`, `core/cli/kickoff.js`, `core/cli/init.js`, `core/web/assets/interview-view.js`, `core/web/assets/settings-view.js`

## Context

ADR-0130 had the concept chat answer in kickoff format 1 and pasted that reply back into YAW for preview and import. In use this was too heavy: a strict task format (spec and acceptance per task) refused real replies, and the round trip through YAW added nothing, because the local coding agent can write the documents itself. The interview also showed three prompts (step 3, Review & apply, Finished). Amends ADR-0130.

## Decision

- The concept prompt asks the chat that holds the concept for one copy-ready block for the local coding agent: fixed instructions to create or update the three foundations, then the adapted concept. It carries only the project setup facts (no documents, no personal answers); the setup wins and conflicts go to open questions. Nothing comes back to YAW; Settings → Kickoff shows the prompt without a paste or import step.
- yaw kickoff concept writes the prompt to .yaw/concept-prompt.md (--stdout prints it).
- The interview shows no prompt on Review & apply. At its end (browser Finished step, terminal yaw init) it offers two alternatives: the concept prompt for another chat, or the local kickoff prompt for the coding agent. The terminal writes the chosen one to .yaw/concept-prompt.md or .yaw/kickoff-prompt.md; both files are git-ignored.
- The foundation action `update` from ADR-0130 stays for kickoff imports.

## Consequences

One paste into the chat, one paste into the coding agent. The agent merges the concept into documents that already exist, so the user reviews its changes in the project instead of in a YAW preview.
