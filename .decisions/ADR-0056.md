# ADR-0056: Review prompts: five separate texts layered project > user blueprint > kit default; headless agent CLIs get the prompt on stdin

- **Date:** 2026-10-24
- **Category:** Modules / Workflow
- **Status:** Accepted
- **Importance:** high
- **Scope:** `modules/review/**`, `core/web/review-prompts.js`, `core/web/assets/review-prompts-view.js`
- **Tags:** review, prompts

## Context

ADR-0055's gate passed the prompt as a CLI argument with outdated flags (claude :* rule syntax, copilot -p) and hard-coded the reviewer texts in the skill. Users need to tune what reviewers look for, per project and as a personal blueprint, from the web UI.

## Decision

Prompts are rules (shared reporting rules), quality, logic, ux, feature. Resolution: .yaw/review/<kind>.md (committed) > ~/.yaw/review/<kind>.md (0600) > modules/review/prompts/<kind>.md. modules/review/lib/prompts.js stores them (symlink refusal, 32 KiB cap, secret-rule check, hash conflict 409). The read-only rule and VERDICT line stay fixed in code. yaw review prompt [kind] and just review-prompt print the effective text; the skill and sub-agents read it that way instead of copied reviewer files. yaw web: Settings > Review prompts (project) and Global > Settings > Review prompts (blueprint). Agent CLIs per vendor docs, prompt on stdin: claude -p --permission-mode dontAsk --no-session-persistence --tools Read,Grep,Glob,Bash --allowedTools Read Grep Glob 'Bash(git diff *)' ...; codex exec --sandbox read-only --ephemeral -; copilot -s --no-ask-user --deny-tool=write --allow-tool=shell(git diff),....

## Consequences

Diffs up to 120 KB no longer hit argument length limits. A team shares project prompts via git; a cached PASS is not invalidated when a prompt changes. Reviewer files are no longer rendered into .agents/skills/review/reviewers/.
